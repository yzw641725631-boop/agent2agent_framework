## Windows 一句话安装

Windows x64 使用同一入口安装桌面端、Skill 和 MCP，正式发行信息保存在 `releases/windows-x64.json`。

在你使用的 AI 开发工具里发送下面这句话，将 Codex 换成实际使用的工具：

> 从 https://github.com/yzw641725631-boop/agent2agent_framework 安装 Agent Hub。我使用 Codex，请按 README 完成 Windows 桌面端、Skill 和 MCP 安装，并引导我登录。

给执行安装的 Agent：获取本仓库的 `scripts/install-windows.ps1` 和 `releases/windows-x64.json`，先阅读安装入口，再从框架仓库目录执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/install-windows.ps1 -Harness codex
```

支持 Windows x64，首批自动配置 `codex`、`claude`、`cursor`。参数可选择多个工具。安装入口校验正式服务器的 EXE 和安装后的程序文件，安装同一发行版的 Skill，合并用户级 MCP 配置；已有设置保留，冲突时停止。初次使用仍需本人登录、完成设备验证，并重新加载开发工具。它不会修改开发工具的审批、信任或沙箱策略。

## 三部分各做什么

| 部分 | 作用 | 存放与发布安排 |
|---|---|---|
| Skill | 告诉 Agent 怎样安装、认领任务、逐轮记录和推进评审 | [skills/agent-hub](skills/agent-hub/SKILL.md)，与同版桌面端一起分发 |
| 桌面端 | 本机登录、运行 MCP 桥接、托盘、推送和在线升级 | 源码与 Skill 放同一个框架仓库；EXE 和更新文件使用现有服务器作为正式下载入口 |
| 服务端 | 身份、邮箱验证、审批、项目权限、文档索引和协作状态 | 运行在现有 `47.109.23.86` 服务器；数据库、Docker 和数据库测试均在服务器 |

框架仓库为 [agent2agent_framework](https://github.com/yzw641725631-boop/agent2agent_framework)，与业务代码仓库分开。`kms` 是拟接入的业务私有仓库；安装框架不会自动获得业务代码权限。MCP 桥接随桌面端提供，用户无需再单独安装一套数据库或 MCP 服务。

- [管理后台](https://47.109.23.86:18180)：后端 **0.14.0**、迁移 **0017**，服务器 PostgreSQL 18.6 + pgvector 0.8.7。支持查看职业职责、共享记忆、任务日志与流程；日志、代码备份和 Git 交付各有独立回执。
- 超管通过安装 MCP 或独立“管理 MCP”列出、创建平台项目，再接入获准的本地工程。
- 项目 MCP 支持任务准入、独占认领、心跳、不可覆盖的工作日志、评审测试和发布确认；PC 与 Web 读取同一组记录。
- 开工准备通过语义和关键词加载获准的已审核长期知识、文档章节与交接摘录，默认记忆部分最多 12,000 UTF-8 字节。本机按账号、设备、仓库与执行实例加密保管；旧原文留档，过时、冲突与退役内容退出默认加载。本地 Agent 可引用原文提交长期知识候选，审核后生效。服务器 CPU 模型只做编码，不调用生成模型 API；索引异步更新，故障时明确降级为关键词检索。
- 创建任务可指定项目经理、架构师、设计或开发职责。PC“项目与 MCP → 部署职责”或固定项目 MCP 可预览并部署七种职业文档、流程与自检脚本；职业不增加人员、仓库或审批权限。

具体步骤统一放在[使用指南](使用指南.md)。日常使用不需要翻阅设计文档。

## 安装后的使用流程

1. 在 PC 端完成本人登录，重新加载开发工具，让 Agent 检查 `hub_connection_status` 与版本。
2. 超管可说：“列出已有项目；没有 kms 就创建标识为 kms、名称为 kms 的项目。”
3. 超管在后台“仓库与资料”登记该项目组的 Web、PC、API 等独立仓库，配置 GitHub App 或该仓库专用凭证，按成员设备审批代码与文档权限。
4. 说“把 kms 接入这个项目组根目录，我使用 Codex”，重新加载后再说“列出获准仓库，只组装这次要开发的 Web”。也可在 PC 绑定根目录、点击“组装仓库”。进入 Web 子目录重新加载其固定仓库 MCP。已有代码可指定 `repository_id` 接入。共享文档按源配置同步，阅读同事日志需单独 `logs:read`。
5. 需要本地职责文件时，在 PC“部署职责”预览并安装。随后在 Web 或项目 MCP 创建任务、指定负责角色并完成准入；通过工程 MCP 认领，准备并阅读职责、规则及共享记忆，再确认准备包，修改前检查路径，每轮保存日志，完成后提交评审、测试与发布确认。详细流程见 [Skill 协作规则](skills/agent-hub/references/task-workflow.md)。

本仓库保存框架说明、桌面端与服务端源码、部署模板及测试。EXE 和在线更新文件继续使用上方的服务器下载入口。

安装连接不读取任意项目文档。不同工程使用各自固定的项目连接；成员权限与真实服务器身份逐次核验。首次登录绑定的账号改变时，需要在桌面设置重新授权，再运行安装入口更新连接。

安装客户端、创建项目组、登记并授权仓库、组装代码和部署职责是不同动作。创建项目组不会自动拉取私有代码。内置职责支持单独部署，自定义职业、跨原文自动综合与跨宿主自动调度仍待实现。
