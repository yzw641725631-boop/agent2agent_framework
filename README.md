# 多项目 Agent 协作框架

让不同设备、不同 AI 开发工具，在授权的项目或项目组内开发、共享记录和交接。第一次了解或使用时，只看本页和[使用指南](使用指南.md)即可。

## 三部分各做什么

| 部分 | 作用 | 存放与发布安排 |
|---|---|---|
| Skill | 告诉 Agent 怎样安装、使用协作工具、读取资料和执行工作流程 | 计划放在本仓库的独立 Skill 目录；尚待制作和发布 |
| 桌面端 | 本机登录、运行 MCP 桥接、托盘、推送和在线升级 | 源码与 Skill 放同一个框架仓库；EXE 和更新文件使用现有服务器作为正式下载入口 |
| 服务端 | 身份、邮箱验证、审批、项目权限、文档索引和协作状态 | 运行在现有 `47.109.23.86` 服务器；数据库、Docker 和数据库测试均在服务器 |

框架仓库为 [agent2agent_framework](https://github.com/yzw641725631-boop/agent2agent_framework)，与业务代码仓库分开。`kms` 是拟接入的业务私有仓库；安装框架不会自动获得业务代码权限。MCP 桥接随桌面端提供，用户无需再单独安装一套数据库或 MCP 服务。

## 现在已经可以使用

- Windows 桌面端 **0.5.0**：[EXE 安装程序](https://47.109.23.86:18180/desktop-updates/win-x64/AgentHub-Setup-0.5.0.exe)。已有客户端可点击“在线升级”。[便携 ZIP](https://47.109.23.86:18180/desktop-updates/win-x64/AgentHub-0.5.0-win-x64.zip)作为可选分发方式。
- [管理后台](https://47.109.23.86:18180)：后端 **0.3.2**、迁移 **0006**，QQ 邮件与超管初始化已完成。
- 超管在 PC 端打开“管理 MCP”，把配置加入 Agent 后，可以用自然语言让它列出、创建平台项目。
- 成员获得设备和项目授权后，在 PC 端绑定工程目录、接入项目 MCP，可以读取已同步的文档和上报进度。

具体步骤统一放在[使用指南](使用指南.md)。日常使用不需要翻阅设计文档。

## 一句话安装：下一项交付

目标是：给 Agent 框架仓库地址和正在使用的开发工具，它安装 Skill、下载校验并安装桌面端、配置 MCP，再引导登录。首次身份验证和必要的设备审批仍需完成。

本仓库保存框架说明、桌面端与服务端源码、部署模板及测试。EXE 和在线更新文件继续使用上方的服务器下载入口。

**可安装 Skill 和一体安装器仍待制作发布，不能把目标流程当成现有功能。** 现有桌面端和服务器继续复用。

安装客户端、创建平台项目、准备业务代码是三个不同动作。创建平台项目不会自动拉取私有代码，也不会部署原 `install.md` 的整套项目组框架。
