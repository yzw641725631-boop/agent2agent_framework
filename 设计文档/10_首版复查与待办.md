## 1. 已修复的实际问题

| 问题 | 修复与验证 |
|---|---|
| 退出登录时仍在等待服务器撤销，本机可同时接收 MCP 请求 | 先冻结本机、清空并保存会话，再请求撤销；正在等待上下文的旧请求也会被拒绝 |
| 晚到的刷新响应可能重新写入已经清空的会话 | 请求绑定客户端生命周期，并核对刷新前后的会话对象；已结束登录不能写回凭证 |
| 项目授权更新时，旧事件流可能随后将新连接标记为已撤销 | 清除旧项目会话时同时取消旧流；已取消的事件和响应不再改变状态 |
| 并发第一次调用可能重复签发同一项目会话 | 同项目首次兑换共用一个进行中的请求 |
| 会话到期、设备撤销可能被当成断网而不断重试 | 分类处理；终止项目流或要求重新登录，退出登录的 IPC 状态不返回历史项目内容 |
| 写权限不足、错误参数会使原本可读的连接变为异常 | 工具错误保留在本次调用，读取连接继续有效 |
| 离线启动不能自动恢复，登记丢包后可能换一把设备密钥 | 离线自动重试；设备身份在登记请求前保存，重试沿用原密钥 |
| 进度流每 90 秒主动断开，重连补齐时不触发新进度通知 | 按 30 秒无数据检测停滞，心跳持续刷新期限；首轮追平后，重连的新记录仍可通知 |
| 移动应用或升级版本后，旧配置阻止再次写入 | 对能核验归属的配置更新应用路径，保留其他项和备份；用户修改过的同名项仍拒绝覆盖 |
| 合法 Unicode 长分页超出桥接响应上限 | 按 UTF-8 字节计数，上限 4 MiB，覆盖本接口的 100 条最大长度记录 |
| stdin 结束时直接退出可能截断大 MCP 响应 | 等待 stdout 自然写完后退出 |

本机测试由 9 项增加为 **21 项，全部通过**。实际 Electron 联调连接服务器隔离 `hub_test` 服务，新增验证已审批权限增加、离线重启后恢复原会话/命名管道及设备撤销。使用两套设备身份在同一 Windows 工作站运行；两台物理设备、macOS 和商业 harness 的端到端验收仍待执行。

`0.1.1` 便携包已验证文件摘要、实际启动、renderer 沙箱与上下文隔离、包内可执行文件启动 stdio 桥接，以及公网 HTTPS 签名请求。后端 39 项测试结果沿用上一轮；本次没有修改或重新发布后端。

## 2. 使用前需要准备

正式库核验为 **1 个用户、0 个项目、1 份站点设置**。空项目列表符合当前数据，需要超级管理员在管理后台创建第一个真实项目，并为其他设备签发该项目授权。测试账号、项目都只在 `hub_test`，未加入正式库。

当前目录 `D:/project/agent_framework` 尚未初始化 Git 仓库，也未连接任何真实项目仓库。Markdown 已存在于文件系统，尚不具备版本化同步和文档索引服务。创建仓库、远端地址、项目文档范围应在接入真实项目时明确。

从 0.1.0 升级需要退出旧托盘后台，启动新版本，并重新预览/写入 MCP 配置以更新应用路径。旧版安装后如果用户又修改了整个配置，缺少足够归属证据时可能需要手工核对并移除旧连接项。
