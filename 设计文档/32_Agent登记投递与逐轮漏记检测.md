# Agent 登记、投递与逐轮漏记检测

日期：2026-11-09。已发布并验证：服务端 0.14.0 / 迁移 0017，Windows 0.16.0；本机程序、Skill 与 MCP 已同步安装。机器可读结果见[本批验收记录](审计数据/2026-11-09_Agent登记投递与逐轮漏记验收.json)。以下区分本批已验证功能与尚未完成的覆盖范围。

## 使用顺序

1. 成员在自己的桌面端登录，进入获准仓库的固定 MCP 连接。调用 `hub_register_agent` 登记当前开发工具、独立实例和承担职业。
2. 负责人从 `hub_list_agents` 选择执行者，读取任务当前版本，用 `hub_dispatch_task` 投递正式待办；PC 和 Web 的“任务与日志”可以看到执行者及投递回执。
3. 执行者通过 `hub_agent_inbox` 查看待办，用 `hub_decide_agent_dispatch` 明确接收、接受或拒绝。接受成功才取得任务运行及租约；随后按原流程准备规则、共享记忆和独立工作目录。
4. 需要逐轮检查时，复制 `hub_preview_turn_hooks` 或 PC 配置窗口提供的 Codex / Claude Code 片段，按宿主要求合并、信任并重新加载。在本轮开始后，用 `hub_bind_work_session` 绑定已经准备并确认的真实运行。
5. 每轮有代码改动就用 `hub_write_worklog` 保存工作说明。用 `hub_get_work_record_status` 检查漏记；日志共享、代码备份、Git 推送分别核对各自回执。

完整参数与状态见 [Skill 使用说明](../skills/agent-hub/references/agents-and-turns.md)。首次安装仍走根目录的 Windows 一体安装入口，宿主钩子需要另外配置；安装桌面端不代表逐轮钩子已经加载。

## Agent 与任务投递

执行者通过固定工程 MCP 登记自己的人员、设备、实例、开发工具、仓库和负责职业。登记只说明可接收任务，不启动外部程序、不扩大权限。实际工具轮询更新最近活动时间，桌面后台在线不能证明模型正在执行。

负责人向明确执行者投递正式任务。投递、接收、接受、拒绝和取消有独立状态与回执。接收不占任务租约；接受在同一事务调用现有原子认领，继续检查任务版本、依赖、路径占用和当前权限。其他人先认领时，原投递不能绕过冲突。离线待办保存在服务器。

登记与投递沿用项目、仓库及人员权限，派工需要 tasks:publish，接收与接受需要本人设备的 tasks:claim 和 tasks:write。撤权、仓库归档、角色或登记版本变化使旧投递不可执行。项目文字不能变成任意 Shell、提示词执行或宿主权限提升指令。

## 逐轮记录

保留现有逐轮显式工作日志和本机加密检查点。新增每个执行实例的漏记状态，将当前实际 Git 证据与最近记录比较；未记录的可观察改动在 PC 显示，并提供 MCP 查询。后台观察只保存代码事实，不编造工作原因与测试结论。

首批提供 Codex、Claude Code 的 Stop 检查入口与配置预览。宿主调用已受信任的钩子后，未记录改动要求 Agent 补写；断网保留检查点并显示待传，撤权走原限定收尾。中断保全与正常结束分别报告。钩子不读取聊天全文、提示词、模型内部推理或未经核验的 transcript_path。

重复 Stop 要有限次数地提醒，不能因持续断网无限唤醒模型。检查只覆盖绑定目录、已准备运行及实际触发的宿主事件；不声称系统写入隔离、七种宿主全覆盖或每次瞬时编辑都可观察。

## 验证结果

### 代码、权限与真实联调

后端完整测试 225 项、桌面完整测试 134 项通过。覆盖并发接单、重复投递、幂等重试、撤权、跨仓库、其他设备重放、登记版本变化、任务依赖和路径冲突。数据库强制行级隔离、列级更新权限及投递状态转换触发器共同限制伪造接受或重写终态。旧工作日志未提供 `turn_id` 时维持原回执兼容。

真实 Windows Controller → 本机 MCP broker → DPoP HTTP → 服务器隔离 PostgreSQL 联调通过，验证了接收不认领、接受原子认领、接受重试、固定仓库、轮次绑定、日志和代码分别取得回执，以及撤权后拒绝待办操作。测试使用一台物理 Windows 上的逻辑身份与设备，不代表不同物理设备或全部开发工具实机验收。

真实 Git 测试验证漏记、补记、断网、同目录多对话隔离、重复 Stop 和中断保全请求。Windows PowerShell 实际执行预览钩子并调用桥接，验证只转交必要的会话、目录和事件字段；提示词、聊天正文及 transcript 路径被剥除。此项验证不代表宿主已经信任、加载或触发了用户工程的钩子。

Web 和 Electron 界面验证使用真实渲染页面和模拟后端，覆盖执行者列表、带版本的投递表单、取消原因、接收与认领区分、漏记提示、钩子覆盖缺口及无横向溢出；服务端权限由独立真实联调验证。

### 部署、恢复与测试清理

数据库和 Docker 测试只在指定服务器运行，本机没有安装数据库或 Docker。服务端升级前保存数据库备份，正式卷继续使用 `agent-hub-postgres-data`，数据库端口不向公网开放；PostgreSQL / pgvector 和共享记忆服务沿用已有部署。

0017 隔离库的非空备份恢复包含 1 个执行者、1 条已接受投递和 1 条含轮次标识的工作日志；恢复后强制行级隔离与状态转换触发器核验通过。正式环境另外完成 0017 备份恢复演练、角色绑定核验与运维巡检。正式平台仍为 0 个业务项目，不将隔离测试或空业务恢复视为真实业务规模验收。

本批 5 个带标签测试容器、2 个测试网络及明确核对的匿名数据库卷已清理。正式数据库卷和共享模型文件保留。巡检确认服务端 0.14.0、桌面签名更新源 0.16.0；持续异地备份和外部告警仍未配置。

### Windows 发布与在线升级

Windows EXE、ZIP 和 metadata_version 17 的 Ed25519 签名清单已发布。隔离配置的已签名 0.15.0 客户端，通过公网检查、下载、校验并原生重启到 0.16.0；未登录客户端也可完成版本检查和升级，登录及项目权限门禁继续保留。EXE 尚无 Authenticode 签名，项目的更新清单签名与 Windows 程序签名分别处理。

本机通过正式一体入口下载安装 0.16.0，沿用 `D:\agent_cache\agent-hub` 数据目录与 Codex 自定义目录。167 个程序文件逐个匹配签名发行清单，11 个受管 Skill 文件匹配包内版本；程序资源目录不存在清单外文件。通过实际 Codex 配置启动 stdio MCP，确认版本 0.16.0、签名更新源可用、登录状态为 `LOGIN_REQUIRED`，没有代替用户登录或验证设备。本人完成 PC 登录并重新加载开发工具后，才能使用本人获准的项目连接。

## 尚未完成的能力

- 当前投递保存待办及回执，执行者明确接受后仍按宿主正常流程开发；没有自动启动外部开发工具或无人值守执行适配器。
- Codex / Claude Code 首批钩子提供配置预览、复制与明确绑定；尚无自动合并安装、宿主启用确认及对应卸载收据。未启用、未绑定、桌面退出或宿主未触发事件时不能保证逐轮覆盖。
- 有界 Stop 提醒不能代替系统级写入限制，也不能保证观察到瞬时修改后还原的所有编辑。日志只陈述实际工作，不自动编造原因或测试结论。
- macOS、其余开发工具逐轮钩子、七宿主整体联动、多物理设备实机、长期容量与效果、持续异地备份和外部告警仍需后续开发或验证。
- 自定义职业、功能说明自动生成任务和获准的本地执行适配器留待后续；本批未开展用户暂缓的正式业务试点，也不构成全项目生产验收完成。
