# 服务端 AI 与操作说明维护

2026-11-10｜服务端 0.16.0 / 数据库 0026 / Windows 0.18.0。

本版将框架自身的共享记忆提炼、功能操作说明起草放到服务端。模型密钥、逐仓库授权、限额、任务执行和调用记录统一管理。Windows、Web、MCP 提交请求和显示状态；成员使用开发工具编写代码时继续使用各自的模型配置。macOS 按用户要求暂缓。

## 1. 如何启用

1. 超管本人登录[管理后台](https://47.109.23.86:18180)。
2. 在“系统设置 → 服务端 AI 调用”填写完整地址，例如 `https://模型服务域名/v1/chat/completions`、准确模型名、密钥和调用上限。模型服务需支持非流式 JSON 对象响应。
3. 保存时密钥输入留空表示保留既有密钥，页面不回显已保存的密钥。
4. 在“仓库与资料 → 记忆整理设置”开启有界资料队列。
5. 在该仓库“服务端 AI”中授权记忆提炼、操作说明起草，按需要分别开启。默认关闭。
6. 在仓库调用记录、共享记忆和功能操作说明中检查结果；知识候选和说明草稿仍需独立审核。

超管需明确同意将该仓库的有限来源摘录发送给配置的模型服务。不要把密钥写入聊天、Skill、工作日志或 Git。仅配置全局模型不代表开启任何仓库。

## 2. 执行与权限

| 环节 | 执行位置 | 依据 |
|---|---|---|
| 原始日志、Git 文档、任务来源 | 服务器保存或索引 | 原文和版本保留 |
| 增量摘录、向量编码 | 现有服务器 Worker | BGE 编码 + PostgreSQL pgvector |
| 有界模型生成 | 独立服务端 Worker | 当前逐仓库超管授权、限额和来源 |
| 知识审核、说明产品/测试核对 | 获准人员 | 独立决定，不由生成任务代审 |
| 代码开发 | 本人授权的开发工具 | 任务租约、规则、专注范围和原有宿主配置 |

后台不创建用户 Token、不签发授权、不运行来源中的命令。授权超管及其设备必须持续有效；操作说明保留原贡献者、设备、实例及冻结来源。普通贡献者也须仍持有当前有效的项目和仓库写入授权。

流程：预留额度与任务 → 持久化调用状态 → 释放数据库连接与锁 → 请求模型 → 加密保存结果 → 重新核对当前权限、来源与租约 → 同事务写入结果和执行回执。撤权与提交沿用项目短事务协调，模型网络请求不占项目锁。

API 运行角色不能更新服务端调用或伪造执行回执。独立 `hub_generation_worker` 无 owner、超级用户或 BYPASSRLS 权限；新增表均使用强制 RLS。普通 Agent 自报模型信息与服务器执行回执分别显示。

## 3. 成本、恢复与网络边界

- 使用兼容 OpenAI 的 `/chat/completions`，单次非流式 JSON 对象，无工具调用，无自动网络重试。
- 可选 `max_tokens` 或 `max_completion_tokens`；可配置输入字节、输出 Token、总时间、每日请求数和每日保守预留上限。
- 项目暂停模式在付费前核对宿主已报告用量、本月服务端保守预留及新请求。保守预留不是精确 Token 账单。
- 提供方返回的输入/输出 Token 独立记录。缺失时显示未知；不捏造用量，也不声称已对账。
- 生产只允许公网 HTTPS 443，拒绝凭证 URL、查询参数、私网/元数据地址、混合公网与私网 DNS、重定向及环境代理。解析后的地址固定到单次连接，保留原域名的 TLS 校验。
- DNS、请求总时间和响应大小均有上限。默认仅一个生成 Worker；同一任务不重复预留付费，仓库轮转避免持续挤占。
- 请求超时、进程中断、结果状态不明时保留预留，不自动重复付费。超管在调用记录中批准“复用已保存结果”，或明确批准新调用。后者等待旧任务租约到期。
- 复用仍需当前授权、配置、来源及任务版本一致；来源已变或任务已被其他执行者接管时保留阻塞状态。

生产模型联调需用户在后台填写真实地址、模型名和密钥。隔离测试服务及合成界面测试不代表真实提供商或业务质量验收。

## 4. 操作说明的后续维护

已发布说明支持反馈、处理记录、完整正文修订、独立产品和测试核对、替换发布、归档、恢复和历史正文。审核期间读者继续看到原已发布正文；搜索不会返回待审修订。修订继承原受众，不能扩大阅读范围。

目录版本 `0` 是随原功能发布的正文；每次发布、归档、恢复都会增加目录版本。并行修订使用基准版本，旧修订不能覆盖新发布内容。维护事件进入审计与项目进度，不修改原说明任务与历史来源。

普通读者可以反馈，只查看自己的反馈；具有来源与发布管理权限的人处理反馈。提交正文修订还需要该仓库 `code:write`。归档项默认隐藏，获准人员可以显式查询和恢复。

MCP 维护工具见[功能操作说明](../skills/agent-hub/references/operation-guides.md)；后台策略工具为 `hub_get_generation_policy`，普通对话看到 `server_enabled` 后不抢占同一后台批次。

## 5. 数据与部署

迁移 `0025` 增加提供方加密配置、逐仓库策略、调用、执行回执和重试申请；`0026` 增加说明修订、独立决定、发布历史、反馈及处理记录。仍使用现有服务器 PostgreSQL，不新增本机数据库。

操作员先建立独立 Worker 角色，再使用 `upgrade-server-0160.sh`。发布前需完整回归、非空旧库升级、当前结构精确恢复、首次 SQL 对比和回退应用兼容证据。未修改的 0.15.1 会拒绝 schema 0026；专用 `0.15.1-schema0026` 回退镜像保留旧业务代码，仅显式声明新数据库版本，并以旧版完整测试核验。升级脚本同时校验正式和回退镜像，按实际数据库版本选择已验证的应用，不回滚数据库或覆盖原卷。备份包含新表；恢复解密还依赖原受控服务器密钥，不应只备份数据库文件。

发布验收结果以本文件后续验收段及审计 JSON 为准。真实业务试点、七种宿主全部真实触发、异地存储/外部告警资源及 Windows 系统代码签名不包含在本版合成验证结论中。
