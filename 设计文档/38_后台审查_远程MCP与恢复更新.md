# 后台审查、远程 MCP 与恢复更新

已发布版本：服务端 **0.19.0 / schema 0030**，Windows **0.21.0**。发布与验收结果见本页末尾和[完整能力清单](33_完整能力开发与验收清单.md)。数据库及 Docker 始终运行在服务器 47，本机不安装数据库。macOS 与真实业务试点按用户要求暂缓。

## 从安装到协作

1. 从框架 GitHub 仓库运行统一 Windows 安装入口。参数支持 `codex`、`claude`、`cursor`、`qoder`、`workbuddy`、`codebuddy`、`trae`。自定义目录用 `-McpConfigPath` 指定实际配置文件，一次一个工具；TRAE 以其 MCP 编辑页为准。安装会合并并备份配置、保留其他连接，通过安装收据追踪归属。
2. 本人在桌面端登录，完成邮箱与设备审批；超管创建项目组并接入独立业务仓库，批准成员在每个仓库的代码与资料权限。安装框架不自动授予业务代码权限。
3. Agent 通过固定项目及仓库的桌面 MCP 认领任务、准备并确认规则，读取有限的共享记忆和同事交接。原 `install.md` 仍保存完整原始制度，按任务生成职责、流程与受管文件，避免每轮全量加载历史。
4. 只要一轮修改代码，就保留该轮目标、变更、验证、阻塞和下一步。界面分别确认日志共享、代码工作树上传、Git 推送和正式流程状态。
5. 交付核验后进入代码审查、独立 CI、评审测试与发布关口。PC/Web 展示同一份服务端进展，提醒不等于执行已经完成。

## 服务端自动代码审查

超管先在“系统设置 → 服务端 AI”填写兼容 OpenAI 的 HTTPS 接口、模型和密钥、超时及日预算；再到“仓库与资料 → 服务端 AI”明确开启“后台代码审查”，选择独立审查账号及其已批准设备。模型密钥加密保存在服务器，不进入 Skill、客户端或 MCP。

审查账号需要 `tasks:review`、`logs:read` 和目标仓库 `code:read`。项目授权、成员、设备及原审批关系必须有效。后台不会自动给超管生成自审理由；参与该任务开发的账号不能成为自动独立审查者。

还需配置仓库“代码规范”和必需 CI。已有“记忆提炼、说明草稿”的授权不包含代码外发，必须另外开启。全局及项目预算继续适用。

执行器固定读取注册仓库、任务基线与交付 SHA，核对完整差异、固定提交文件和 Git blob 摘要；不克隆执行仓库、不运行仓库脚本、不请求模型给出的网址。最多 40 文件、85 次提供方请求、45 秒源码读取，并受实际输入字节预算约束。超过预算、二进制、未覆盖文件或缺少基线均留下缺口，不能报告通过。大变更应拆任务或由获准审查者补足。

报告来源为 `exact_git_objects`，区别于本机 `exact_checkout` 和不能独立证明远程提交的 `archived_worktree`。每条规范、任务范围、授权及全部变更路径均须覆盖。模型输出缺少来源缺口时由服务器补入；模型结论不能替代 CI。

任务保存完整审查历史，提交号、范围或规范变化时重新审查。调用前和提交前都重新核验授权。撤权后的结果加密保留并拦截；超时、断网导致计费未知时不自动重复付费调用，由超管选择使用已保存结果或明确批准新调用。待办返回 `execution_policy.server_enabled` 时，Skill 不重复抢占后台工作。

## 可选择的远程 MCP

桌面 MCP 继续承担完整本机开发。远程入口提供云端资料读取和进展协调，适合支持 HTTP MCP 与预注册 OAuth 的宿主；不承诺所有宿主的 OAuth 均已实机互通。

| 操作 | 入口 |
| --- | --- |
| Git/worktree、本机执行、逐轮钩子、代码快照、安装及撤权卸载 | 本人登录的桌面 MCP |
| 项目与任务状态、共享日志索引和原文、文档分段、关键词记忆查询 | 固定仓库远程 MCP |
| 进展通告 | 远程连接须有 `mcp:coordinate` 及平台 `tasks:write`；不代替正式任务提交 |

使用方式：

1. 本人在目标浏览器登录后台，完成新设备验证和审批。在“远程 MCP 连接”复制当前浏览器设备 ID。
2. 超管在此页批准新连接，固定本人账号、已批准浏览器设备、项目授权和仓库，填写宿主给出的完整回调地址。普通成员须选其本人、该设备的有效授权；超管不需要项目授权。
3. 页面返回客户端 ID 和固定入口 `https://<服务地址>/mcp/projects/<项目ID>/repositories/<仓库ID>`。把它们填入支持预注册的宿主配置；令牌由宿主的 OAuth 流程接收，不发到聊天。
4. 宿主发起授权，本人在注册的同一浏览器设备登录并确认。若登录后台默认选了其他已获准项目，会切换到注册时批准的项目授权，再确认。
5. 本人可在后台断开自己的会话；超管撤销客户端后，相关访问和刷新立即失效。

协议提供 OAuth 发现、受保护资源发现、精确回调和资源绑定、S256 PKCE、一次性五分钟授权码、有界表单解析、短期访问凭证及轮换刷新；刷新凭证重放撤销该 OAuth 会话族。仅保存令牌摘要。正常源会话刷新继续有效，注销、密码恢复、设备或项目撤权均重新拦截。远程 Bearer 凭证不具备桌面私钥持有证明，必须由客户端妥善保存。

Streamable HTTP 支持 JSON POST、Origin 校验、注册来源 CORS、协议版本协商、64 KiB 请求与60 KiB回复上限；此入口不提供 SSE，GET 返回405。业务工具失败回滚本次写入，不能一边返回错误一边保存部分进展。无动态客户端注册、无任意客户端元数据 URL 抓取、无任意 Token 转发。

远程请求不能在不持有本机工作树的情况下上传和卸载。撤权交接仍由桌面检测、限定上传和安装收据清理执行；断网或上传失败保全本机工作。

参考：[MCP 授权规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization)、[Streamable HTTP](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)。这不是协议认证或所有宿主实机兼容的声明。

## 离线保存的恢复码

后台右上角“离线恢复码”要求当前密码，生成10个随机恢复码，只显示一次。数据库仅保存 HMAC 摘要；旧码在重新生成后失效，两年有效。关闭显示即清除页面内容，恢复码不进入持久化请求重试缓存。

登录页选择“使用离线恢复码”，联网提交登录名、一个恢复码和新密码。这里“离线”指用户将码另存一处；不能在服务器断网或数据库丢失时恢复服务。

恢复会使整批旧码、旧会话及原项目授权失效，冻结原工作交接。它不批准新设备、不跳过邮箱验证码，也不恢复被移出的项目权限。并发使用同一码只有一次成功；新设备继续按邮箱及超管审批规则处理。

## 更新根密钥轮换与 Windows 证书

更新包继续使用原 Ed25519 初始根。支持随签名清单附加连续 `root_chain`，每个新根必须由旧根阈值及新根阈值共同签署，最多4把公钥、阈值1至4，版本逐一递增、根有效期最多366天。每次链最多16次轮换，达到后需发布新初始根版本并保留可核验的升级路径。在线更新拒绝根版本回退与过期根；历史包仍可用于恢复启动。

操作脚本位于桌面 `scripts/rotate-update-root.cjs` 与 `scripts/sign-release.cjs`。先离线产生并保存新私钥，再生成双签根链；用 `--root-chain`、`--additional-keys` 满足新阈值。旧客户端过渡期可使用 `--bridge-key` 保留原单签名。更新服务端巡检与客户端一起验证根链，不能提前删掉旧私钥或声称未升级客户端已经接受新根。本次未实际轮换生产密钥。

Windows Authenticode 支持指定受保护证书库中的证书指纹和 `signtool.exe`，程序及安装EXE在生成摘要前签名并校验证书签名。`HUB_REQUIRE_AUTHENTICODE=1` 在缺证书时使打包失败。私钥不进入项目；本次没有用户提供的证书，因此发行包仍只有框架的 Ed25519 更新签名，不是 Windows 证书签名。
