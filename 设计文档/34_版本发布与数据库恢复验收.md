## 2. 版本升级与数据保全

| 验证 | 方法及实际结果 |
| --- | --- |
| 正式 0.14.0 / 0017 → 0.15.0 / 0024 | 同一事务快照导出，逐表核对旧列及记录摘要；保全 45 张旧业务表、63 条记录。只排除必须变化的 Alembic 迁移版本行，不将它计入保全数 |
| 正式 0.15.0 → 0.15.1 | schema 0024 不变；精确比对 61 表、64 条记录及所覆盖结构，完全一致 |
| 旧程序兼容 | 0.14.0 在 0024 上通过 225 项完整回归；保留旧镜像。仅支持已验证的本次回退范围 |
| 新程序源码一致 | 核验运行镜像中的 45 个应用文件，与通过回归的源码一致 |
| 新程序启动约束 | API 要求匹配 schema；运行角色只能读取迁移版本，不能改迁移历史；权限测试通过 |

升级时先取得部署锁、再取得备份锁，暂停写入进程，保存一致快照，迁移和核对后启动工作器，检查公网健康、静态资源与未登录访问拒绝，再切换 `current`。失败时重启上一程序并保留数据库与备份；没有自动覆盖生产数据。

当前源码 `deploy/upgrade-server.sh` 是已使用的 **0.15.0 → 0.15.1** 操作员入口，要求版本、镜像、文件摘要和验收回执精确匹配。它不是任意历史版本的通用升级器；0.14.0 → 0.15.0 的原始入口及证据留存在服务器对应的不可变发行目录。

## 3. 备份到底备什么

- **数据库**：账号与权限、设备、项目和仓库配置、任务、工作日志、资料原文、记忆卡片、知识审核、向量、流程和交接记录。
- **已上传工作**：服务器已接收的加密代码工作树档案。尚未上传的本机修改不在服务器备份内。
- **恢复配置**：数据库角色、受控应用/数据库配置和语义模型。restic 加密密钥另行保管，不能只留在这台服务器。

Git 继续保存源码和提交历史。工作树档案不包含完整 Git 历史、被排除的本机凭证或任意忽略文件。备份结果、日志共享、代码上传、Git 推送和部署回执各自核验。

新版备份清单为 schema 2：同一个 PostgreSQL 导出快照生成 dump 与逐表摘要，同时保存 dump、角色清单和数据清单的 SHA256，以及对应程序版本、schema 和不可变镜像 ID。恢复使用该快照的镜像，不再固定运行旧版。历史 schema 1 备份仍按明确的 0.14.0 / 0017 兼容路径恢复，但不能声称它们已有新的数据清单证明。

数据清单仅含表名、列名、计数、摘要和结构指纹，不包含记录正文。精确恢复覆盖数据、列，以及本次工具检查的 RLS、表/函数有效权限、约束、策略、索引、触发器和函数；这不代表已验证整个 PostgreSQL 集群的所有设置。

## 5. 首次安装 SQL 修复

上线后的补充验收发现，0.15.0 离线导出会把 PostgreSQL `%ROWTYPE` 写成 `%%ROWTYPE`。在线 Alembic 迁移正常，正式数据未受影响。0.15.1 为离线编译明确使用 `paramstyle: named`，重新生成 `deploy/02_schema.sql`。

修正后的 SQL 已在服务器全新隔离库完整执行，61 表结构与升级库一致。正式服务器仅更新将来空卷使用的初始化文件，没有在现有正式卷重跑初始化 SQL。
