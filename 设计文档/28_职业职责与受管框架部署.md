# 职业职责与受管框架部署

日期：2026-11-09。发布版本：服务端 0.10.0 / Alembic 0013，Windows 0.12.0。

## 本批范围

原 `install.md` 的项目组、职业分工、专注范围、按需读取和逐轮记录，逐步落到现有授权协议中。本批补齐内置职业与受管文件部署；不把旧共享模式开关搬进多人工作区。

| 部分 | 实际行为 |
|---|---|
| 职业 | 项目经理、架构师、产品与交互设计、开发、代码审查、测试、发布 |
| 任务 | 创建时指定四种主执行角色之一，默认 developer；服务器绑定认领角色 |
| 开工 | schema 3 准备包加载当前职责、规则、范围及预算内获准记忆，一起哈希确认 |
| 恢复 | 本机加密保管职责和记忆，联网验证当前租约、职责、规则与来源后加载 |
| 流程 | 需求、设计、可行性、评审、测试、发布均记录真实人员、设备、harness 与职业 |
| 工程部署 | MCP 或 PC 预览后，按 preview_hash 部署固定工程的职责、流程、索引和自检脚本 |
| 撤权 | 冻结所有主执行角色；限定上传成功后按安装收据清理职责、脚本、测试和 MCP 项 |

职业不产生人员、仓库或审批权限。主执行共用唯一 active 租约，不允许同一任务被不同角色重复认领。评审仍沿用独立作者检查，超管自审例外显式留痕。

## 文件与语言

目录固定为 `.agent-hub/framework/<连接名称>/`。默认生成 12 个文件：`main.md`、`doc_index.json`、七份角色说明、`workflow.md`、`scripts/check-framework.cjs`、`tests/framework.test.cjs`。`doc_name_lang` 与 `doc_content_lang` 可分别为 zh/en；文件名选择适用于角色目录与角色文档，固定协议入口名称不变。

文档来源为版本化内置职责目录。自检代码由桌面模板生成，服务器不提供任意 Shell 或可执行代码。部署只写文件；用户可自行执行 Node 自检和测试。自检证明本地文件完整性，不证明当前远程权限。

每个连接有独立安装收据。框架更新的文件备份保存在桌面数据内，避免在工程留下未登记 `.bak`。本机职责文件不自动提交到业务 Git。工作观察仅忽略收据登记的未跟踪配置和框架路径；已跟踪改动、其他未跟踪业务文件仍须通过范围与保护路径检查。原文档索引是本地框架索引，远程共享资料继续使用服务器文档索引和来源权限。

用户改过的受管文件不自动覆盖或删除，清理报告显示冲突并保留文件。多连接共用目录时只清理本连接归属文件，公共 Skill、其他项目、业务代码和检查点继续保留。

## Token 与记忆

一次开工只加载当前职责，不全量注入七份角色说明。仅在拆解或查阅分工时调用职业目录。服务器仍使用有来源的确定性摘录、增量队列、版本失效和预算控制；pgvector 的存在不代表已配置 Embedding 或语义模型。

公开文本分词测量：当前架构师职责约 172 个 `o200k_base` Token，完整职业目录约 1,265；Skill 入口约 1,930，仓库开发连接的 36 个工具定义约 4,794。工具和所选参考文档仍有上下文成本。本次隔离样例的记忆段约 856，默认预算仍为 12,000 UTF-8 字节。以上均不是 Astra 账单、真实团队消耗或已测得的费用节省，详见 [Token 测量](审计数据/2026-11-09_0120_Token测量.json)。

角色变更、规则变更、已用来源失效后要求重新准备。删除本机派生记忆和职责时保留已确认的代码基线，确保撤权最终采集可继续。

## 尚未解决的总体要求

- 自定义职业目录与项目职业修订、任务依赖图、跨宿主自动调度、并行 worktree 及文件冲突协调。
- 全部七种 harness 的真实逐轮/中断钩子、macOS 打包与实际设备验收。
- Embedding 模型与数据发送范围、语义召回、长期模型蒸馏及语义冲突质量评测。
- kms 私有仓库真实团队试点；当前正式平台尚无业务项目数据。
- 持续异地备份、外部告警、保留策略与服务器 OS 迁移。

本批通过验证不等于整个框架已经满足生产验收。项目文字规则和 MCP 检查也不等于操作系统级文件写入沙箱。
