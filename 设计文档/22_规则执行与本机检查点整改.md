## 新的代码任务流程

1. 管理员创建代码任务（默认 `observed`），填写仓库、目标端、允许路径和验收标准，完成三项准入。
2. 执行者通过工程 MCP 认领，首次准备使用干净 Git 根目录或独立 worktree。
3. `hub_prepare_work` → 实际阅读规则及必要原文 → `hub_acknowledge_work`。
4. `hub_check_changes` 核验当前规则、租约与拟改路径；每轮修改后 `hub_write_worklog`。
5. 桌面先落加密检查点，再上报日志和清单。只有 `server_confirmed: true` 才表示共享；断网为 pending，旧规则或撤权为 blocked。
6. `hub_submit_task` 重新核验实际清单和最新日志；之后沿用评审、测试和发布关口。

网页与桌面是不同设备身份，代码任务由工程 MCP 认领。网页用于配置规则、拆解和流程确认；显式 `declaration` 人工资料任务保留网页记录流程，不提供实际代码证据保证。旧任务迁移后保持 declaration，不伪造历史证据。

## 保存、恢复和安全边界

服务器使用现有 PostgreSQL，新增规则版本和上下文表；规则不可覆盖，上下文只允许更新确认时间，按项目、用户、设备与运行范围应用 RLS。日志 API 核验上下文与改动清单；数据库本身不独立验证全部流程语义。本轮没有在电脑安装 PostgreSQL 或 Docker。

桌面检查点逐条使用系统凭证保护加密，原子落盘，不提供明文回退。绑定账号、设备、服务器和工程。每个最多 100 个文件、4 MiB/文件、16 MiB 内容；本机最多 100 条。手动日志的独立检查点不被后台观察覆盖。

后台每 15 秒调度：约每分钟采集变化，约每 2 分钟续租；连续 10 分钟没有实际代码或工具活动就停止续租。断网仍可保全已准备运行的本机工作，恢复后重试 pending 日志。退出后台或系统凭证无法解锁时，这些能力停止。观察失败在 PC 显示，不伪装成已保存。

代码清单覆盖基线以来的已提交、暂存、未暂存及非忽略的未跟踪文件；文件名、哈希、大小和模式进入日志，内容只留本机。Git 忽略文件不采集；符号链接、目录联接逃逸、submodule、冲突、类型变化和超限文件拒绝。内置敏感路径和私钥标记检查只是部分防护，不是完整秘密识别。

导出只写入新目录，含 `checkpoint.json`、变更文件和删除清单。恢复须另取原 Git 基线，核对后应用。只为已经共享且已导出的检查点提供显式清理，清理前重验原文和文件哈希；待发、被拦截和后台观察副本保留。检查点不是完整仓库备份。

服务器接收的是本机观察器的声明，未独立下载代码核验哈希；持有合法访问身份的恶意客户端仍可能伪造清单。不能据此声称任意本地开发被强制隔离。`local_code_backup: true` 与 `server_code_backup: false` 分别表达本机保全和没有远程代码副本。
