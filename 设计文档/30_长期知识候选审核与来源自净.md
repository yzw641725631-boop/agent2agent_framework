# 长期知识候选、审核与来源自净

日期：2026-11-09。已发布版本：服务端 0.12.0 / Alembic 0015，Windows 0.14.0。

## 解决的问题

原有逐轮日志与文档章节完整留档，同任务的较新交接会替代旧交接；长期有效的接口、决定和经验缺少独立生命周期。本批增加由本地 Agent 或人员提炼、带单个原文引用、经审核后生效的长期知识。

| 层级 | 本批行为 |
|---|---|
| 日志与文档原文 | 不覆盖、不因提炼删除，沿用原始资料权限 |
| 交接与章节卡片 | 增量规则摘录，继续保留版本及原文入口 |
| 长期知识 | 候选 → 独立审核 → 生效、冲突、退役、驳回或替代 |
| 开工记忆 | 相关有效知识与交接共用 12,000 UTF-8 字节预算 |

本地 Agent 已有模型上下文，可以将新增长期结论通过 MCP 提交。按内容变化触发，普通进度继续写日志；服务器没有新增云模型调用或模型凭证。生成工具、模型和 Token 用量均明确为作者报告。

## 存储、引用与权限

新增 `memory_facts` 和追加的 `memory_fact_events`。每条知识绑定一个来源 `memory_cards`，使用项目复合外键，保存引用摘要、逐字摘录、主题、正文摘要和生成记录。正文不可由运行角色改写；状态投影和追加决定在数据库提交时必须一致。两张表强制 RLS，继承来源卡片、原文、仓库和日志读取权限。

普通成员有 tasks:write 且可读来源时可提候选；tasks:publish 且可读来源者可处理审核。作者不能独立批准自己的候选，超管自审须保存明确原因。MCP 固定仓库自动限定查询、提交及审核范围。幂等响应之前重新检查引用或候选读取权。

一条知识绑定一个来源，避免跨资料拼接后的权限交集不明确。跨原文结论暂按独立条目保存；模块汇总、向量召回和跨原文语义推理留待后续实现。

## 同主题协作与自净

`(project_id, resource_id, topic)` 的部分唯一索引确保同一范围同一主题只有一个 active 结论。审核沿用项目事务锁；替换须提供旧知识 ID 与版本，双方决定在同一事务留存。不可见的占用只返回通用冲突，不导出其 ID、正文、作者或数量。

新日志只替代交接，不自动使已审核的长期知识过期。原始卡片退役或冲突、当前文档换版或删除、文档源配置变动时，数据库触发器将相关生效知识置为 source_stale 并追加自动记录。文档同步的删除及换版检查延迟到事务末尾，内容未变时不产生误失效。

撤权由原文 RLS 立即阻断，无须等处理队列。旧准备包也继承来源读取要求；已经载入的知识版本变化或退出 active 后，后续受管修改检查与提交要求重新准备。正式权限、专注范围和保护路径继续由项目规则控制，知识正文不授予权限。

## 用户入口

新增 MCP：`hub_search_knowledge`、`hub_propose_knowledge`、`hub_decide_knowledge`。Web“共享记忆”支持摘录与长期知识切换、提交候选、审核及明确替换；PC 提供长期知识、候选与历史查看，以及原文展开入口。用法见[长期知识 Skill 参考](../skills/agent-hub/references/knowledge.md)。

## 验收状态

后端 198 项、桌面 126 项测试通过。覆盖逐字引用、来源摘要、候选幂等、作者自审拒绝、超管例外、并发同主题审核、明确版本替换、跨项目和跨仓库拒绝、来源失效、不可变正文及追加决定一致性。提交和审核的旧幂等请求在来源撤权后均不能重放读取；不可见主题占用只返回通用冲突。

回归发现并修复了重复同步误失效：失效触发器以数据库迁移所有者运行，旧表的强制 RLS 隐藏当前文档。新增仅限该后台角色的 SELECT 策略；运行角色仍按原文授权读取。文档删除及换版在事务末尾核验，未变同步保持知识版本，真正换版与配置变化仍使知识失效。

真实 Windows Controller → DPoP HTTP → 服务器隔离 PostgreSQL / Memory Worker 联调通过：候选批准前不加载；另一逻辑身份批准后进入开工及本机加密记忆；来源冲突阻断旧准备包并清掉本机投影；同任务更新交接后，长期结论继续由下一位成员加载。撤权收尾上传、框架卸载和业务代码保全继续通过。测试使用一台物理 Windows，多个逻辑身份与设备，不代表真实团队或跨操作系统实机验收。

Web 与 Electron 的真实界面、模拟后端验证通过，包括多行逐字引用、候选历史、带版本明确替换、自审原因输入以及按 source_card_id 展开原文。界面测试不代替服务端权限验证。

0014 → 0015 升级保留旧活跃任务、原日志、记忆卡片与已确认准备包。隔离数据库的非空备份恢复包含 1 个文档版本、5 张来源卡片、2 条长期知识和 5 次决定，来源、内容摘要及状态审计通过。正式库也已完成新版备份恢复与巡检；正式平台尚无业务项目，恢复中的业务数据为零，本次没有开展用户暂缓的业务试点。

正式服务端、Worker 与迁移已部署，数据库仍仅在服务器运行，正式数据卷保留且数据库端口没有公网暴露。Windows 0.14.0 EXE、ZIP 和递增到 15 的 Ed25519 签名更新清单已发布。隔离旧客户端通过公网从 0.13.0 升级并重启到 0.14.0；本机一体安装成功，已核验 163 个程序文件、10 个同版 Skill 文件，并用实际安装配置完成 stdio MCP 版本检查。需要用户本人登录，未绕过鉴权。EXE 尚无 Authenticode 签名。

本轮联调的开工记忆约 3.6 KB，限额仍为 12,000 UTF-8 字节；没有据此推算实际模型计费 Token 或长期节省率。完整结果见[长期知识与来源自净验收](审计数据/2026-11-09_长期知识与来源自净验收.json)。
