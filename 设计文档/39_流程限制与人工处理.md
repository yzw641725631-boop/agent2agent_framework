# 流程限制与人工处理

2026-11-11 已发布｜服务端 0.20.0 / 数据库 0031 / Windows 0.22.0，签名更新序号 23。完整结果见[发布验收数据](审计数据/2026-11-11_0220_流程限制与人工处理发布验收.json)。

## 怎样使用

1. 正常创建、认领和开发任务。网页“任务与日志”和 PC 的同名页面显示失败计数、当前阶段期限及处理历史。
2. 默认单环节累计 **3 次不通过**、测试累计 **2 次退回开发**，或当前阶段达到 **24 小时**，任务暂停并转人工。相同请求的幂等重试不增加次数，正常进入测试不算退回。
3. 暂停后停止开发、推送、提交和流程决定。当前运行的原人员和原设备仍可保存已有日志、上传获准代码工作树；保护路径和仓库授权继续生效。上传失败或断网时保留本机加密检查点。
4. 负责人打开网页任务详情，选择“负责人处理并恢复”，填写失败原因、解决措施与后续安排，并输入本人当前密码。恢复开始新的处理周期，旧计数和历史保留；开发任务重新认领，旧执行凭证不可继续使用。
5. 网页“岗位与流程 → 调整流程限制”允许有 `tasks:publish` 权限的负责人保存新阈值与批准原因。仅影响新建任务，不回写已有任务的阈值或计数。

## 计时和权限

- 准入、开发、评审、测试和发布确认各自计时。首次待认领排队没有开发期限；开工后释放、接手和正常心跳不会重置同一开发阶段的期限。退回后进入新的开发阶段，失败计数仍在当前周期内累计。
- 本次迁移给旧任务建立新的计时基线，不因历史创建时间立即批量暂停。旧失败决定原文保留，升级后新周期从零计数。
- 数据库触发器维护计数、期限和暂停状态，应用运行角色不能直接覆盖控制字段。旧客户端也不能靠认领、续期或提交绕过暂停。
- 现有独立记忆工作器每约 30 秒发起一次有界超时巡查；事务只尝试项目锁，忙项目留待重试。读取时即检查有效期限，巡查排队不能使已过期任务继续开发。
- 只有有权负责人可以恢复；接口要求本人密码、当前任务版本、当前处理修订和原因。MCP 不提供恢复工具，不替负责人收集密码。密码和恢复请求不进入持久幂等缓存。
- 系统超时通知明确标记为系统来源，不冒充用户或设备。处理原因与完整历史按日志及仓库权限读取，公共动态只包含任务状态。
- 流程暂停不等于撤权，不触发卸载。撤权仍执行已有的限定交接、工作保全与按安装收据清理，不能因任务暂停而失效。
