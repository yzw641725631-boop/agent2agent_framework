# 桌面进程退出与崩溃恢复验收

2026-11-11｜对应原计划阶段B“可靠交接”、阶段D“跨端协作”的Windows恢复验收，补齐[上轮联调](42_双仓库协作与断网恢复联调.md)尚未执行的完整Electron主进程退出/重启。被测版本为服务端0.22.0 / schema 0032、Windows源码0.23.1。

## 实际执行范围

在一台Windows电脑，以独立合成账号和临时目录启动实际`main.cjs`，保留真实Controller启动、账号与权限恢复、BrowserWindow、preload IPC、stdio MCP、Windows系统加密和退出清理。每次恢复均先等待旧主进程确实结束，再启动不同PID的新Electron主进程；没有在同一应用内重建Controller来代替进程重启。

Node测试父进程负责启动及观察Electron。合成身份通过单独的Electron进程写入DPAPI加密Vault，该进程结束后才启动被测桌面。故障只注入父进程的本地HTTP中继和本次创建的子进程句柄，不改桌面业务方法、主入口或服务端业务逻辑。

数据库与HTTP夹具沿用服务器47的隔离`hub_test`，512 MiB内存、1.5 CPU、无swap。测试库、专用测试网络和随机种子密钥沿用[42号记录](42_双仓库协作与断网恢复联调.md#复现入口)的隔离要求。主机实际公网服务和数据库生产卷单独核验。

## 四个场景全部通过

最终完整运行耗时29.912秒。Electron 45.2.3、内置Node 24.22.2。逐场景进程ID、退出信号、时间、回执摘要和源码摘要见[验收数据](审计数据/2026-11-11_桌面进程退出与崩溃恢复验收.json)。

| 场景 | 退出前状态与故障 | 重启后的结果 |
| --- | --- | --- |
| 正常退出待传 | 断网保存加密检查点，日志未共享；调用app.quit，真实before-quit清理后退出码0 | 新主进程在离线状态找到原待传记录；联网刷新并从真实页面IPC重试后，日志和代码分别确认 |
| 强制终止待传 | 检查点已持久保存后强制终止主进程，不执行before-quit | 新主进程重新解锁Vault与检查点；待传可恢复，补传形成1条日志及独立代码回执 |
| 日志回执丢失后强制终止 | HTTP中继先让服务器提交日志，再丢弃成功响应并断网；客户端仍显示pending，然后强制终止 | 服务器重启前已有1条日志；补传沿用原操作ID和原日志，重试后仍只有1条 |
| 代码回执丢失后强制终止 | 日志已共享，服务器已接收代码备份，中继丢弃代码成功响应并断网，然后强制终止 | 客户端从磁盘恢复“日志已共享、代码待确认”；补传复用服务器原快照ID和回执，不重复生成 |

每个场景均核验：

- 旧、新Electron主进程PID不同，旧进程已结束；强制终止使用父进程持有的本次子进程句柄，不按历史PID杀进程。
- 本机检查点为Windows加密文件，未包含合成工作说明明文；离线重启也能在真实桌面“本机检查点”接口找到原记录。
- 恢复网络后，经真实preload IPC执行刷新及检查点重试；再次重试返回相同日志ID与代码回执。
- 服务器每任务最终恰有1条日志。丢失回执的场景还比对重启前后已提交日志、快照及回执身份。
- 从服务器下载实际备份，验证未提交文字、二进制内容、删除状态和未变基线；原工作目录保留相同文字、二进制和删除结果。

## 复现入口

- [check-desktop-restart.cjs](../projects/agent-hub-desktop/scripts/check-desktop-restart.cjs)：通过Node运行的父进程，创建真实Electron进程、本地中继和MCP子进程，并执行四个场景。
- [desktop-restart.worker.cjs](../projects/agent-hub-desktop/tests/desktop-restart.worker.cjs)：仅供验收使用，通过独立随机命名管道接收固定种类的请求；桌面分支加载未修改的`main.cjs`，通过真实页面`window.hub.invoke`调用状态、检查点及重试入口。
- 服务端使用已有[collaboration_http_fixture.py](../projects/agent-hub/tests/collaboration_http_fixture.py)，每次完整验收前重置隔离夹具。与其他会清空`hub_test`的测试串行运行。

运行前确保Windows已有Git、桌面依赖及Electron；仅服务器运行PostgreSQL与Docker。先通过SSH将服务器回环`18768`转到本机回环`18769`，本机`18768`留给父进程中继。设置`HUB_TEST_HTTP=collaboration-only`、受控`HUB_TEST_FIXTURE_KEY`以及绝对路径`HUB_DESKTOP_RESTART_REPORT`，报告文件须尚不存在。不要把种子密钥写入命令参数、Git或验收报告。

在仓库根目录执行：

```powershell
node .\projects\agent-hub-desktop\scripts\check-desktop-restart.cjs
```

被测桌面使用独立`AGENT_HUB_TEST_DATA`目录和隐藏窗口，不打开本人账号资料。正常退出调用真实`app.quit`；异常退出通过本次进程句柄强制终止。父进程关闭连接并核验临时目录位于本次创建的根目录后清理合成资料。

## 结论与边界

本轮新增验收代码、证据及进度说明；被测桌面主入口、Controller、Vault、WorkStore和HTTP业务实现沿用既有版本，未发生产品运行代码修复或新版本发行。

验证的是未打包Windows源码入口，测试模式下托盘通知及在线更新未激活；不能据此替代已安装EXE、在线升级及托盘交互的组合验收。强制终止发生在检查点已经保存或服务器已经提交之后，没有模拟磁盘写入中途断电、文件系统损坏、操作系统重启或整机故障。

只有一台物理电脑，没有启动真实Codex/Claude Code宿主或调用生成模型；双人双机、各宿主原生事件、真实业务质量与费用、异地灾备等验收仍保留。真实业务试点与macOS继续暂缓。

测试结束后移除HTTP夹具、专用回环网络及随机密钥文件，恢复隔离数据库先前的停止状态。正式0.22.0、数据库0032、生产卷及网关健康保持核验通过。本工程仅有安装MCP连接，当前桌面后台离线；本轮工作记录保存在仓库，没有固定项目MCP日志共享回执。

下一项可在服务器隔离环境继续进行并发与容量故障演练；需要外部设备、模型或异地资源的项目仍按原清单保留。
