# 管理后台与首次初始化

> 2026-11-05｜Agent Hub 0.2.0 已部署 `47.109.23.86`。邮箱、SMTP、服务域名在页面配置，不需要发到聊天里。

## 1. 打开后台

现在可直接打开公网 [管理后台](https://47.109.23.86:18180)，使用 IP 和端口，无需域名。入口使用受信任的 IP HTTPS 证书。超级管理员已经建立，首次初始化已关闭。

**首次改用新网址时会被识别为新浏览器设备。** 在新网址登录并完成邮箱验证后，回到原来建立超管的浏览器和 SSH 转发入口，刷新并重新登录，在“授权审批”批准该新设备，再到新网址点击“检查审批并继续”。保留原可信浏览器的网站数据，设备审批规则继续生效。

原 SSH 入口继续保留。API 绑定服务器 `127.0.0.1:8765`，在 Windows PowerShell 或 macOS 终端建立 SSH 转发：

```sh
ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -L 127.0.0.1:18765:127.0.0.1:8765 root@47.109.23.86
```

保持终端连接，在原可信浏览器打开 [SSH 转发入口](http://127.0.0.1:18765)。SSH 使用服务器现有登录凭证；数据库账号不用发给设备。

首次初始化码保存在服务器 `/opt/agent-hub/application/setup-token`，权限 `0600`。通过服务器管理终端读取，也可以另开终端执行：

```sh
ssh root@47.109.23.86 cat /opt/agent-hub/application/setup-token
```

初始化码只用于首次建立超管，不能用于日常登录。当前超管已经建立，下节保留首次安装步骤供后续空实例部署参考；现有实例应登录后在“系统设置”维护发信配置。

## 2. 首次建立超管

1. 在初始化页面输入服务器初始化码；若之前已经保存过设置，先点击“读取已保存设置”。
2. 填写 SMTP 主机、端口、发信邮箱、账号和密码/授权码，保存发信设置。支持 TLS（通常 465）和 STARTTLS（通常 587）。
3. 服务域名可以先留空；页面只接受 HTTPS 地址。
4. 填写超管登录名、至少 12 个字符的密码、邮箱和设备名称，发送邮箱验证码。登录名为 3–80 位小写字母或数字，可含 `._-`，以字母或数字开头；`root`、`641725631` 都有效。
5. 输入实际收到的八位验证码，建立唯一超管及第一台可信设备。

没有正确验证码不会创建超管。验证码绑定当前浏览器设备和发信设置版本，十分钟有效、五次失败后失效。发信设置修改后需要重新发送；同一设备重发间隔为六十秒。

初始化完成后，所有初始化配置与创建接口都会拒绝再次操作，即使仍持有初始化码。后续配置由超管登录后的“系统设置”维护。

### 改用 QQ 发信

服务器至 QQ 的两种加密连接均已测通；推荐在页面填写：

| 后台字段 | 填写内容 |
|---|---|
| SMTP 服务器 | `smtp.qq.com` |
| 端口 | `465` |
| 连接加密 | `TLS（通常为 465）` |
| 发信邮箱 | 你的完整 `xxx@qq.com` 邮箱 |
| SMTP 账号 | 同一个完整 QQ 邮箱 |
| SMTP 密码 / 授权码 | 在 QQ 邮箱新生成的 SMTP 授权码 |

在 QQ 邮箱网页版开启 IMAP/SMTP 服务并生成授权码，入口和验证方法见[获取 QQ 邮箱授权码](https://consumer.huawei.com/cn/support/content/zh-cn16108643/)。授权码直接填入后台。切换服务商必须填写新授权码；密码框留空会保留旧值。保存后，再到“建立超级管理员”发送验证码；超管收件邮箱可以继续用 Gmail，也可以填 QQ。

此前 Gmail 多次在 TCP 连接阶段超时，尚未进入密码认证。用户已将发信设置改为 QQ，当前保存为 `smtp.qq.com:587/STARTTLS`，并已确认收到验证码邮件；当前配置可以保留。页面已分别提示连接、认证、加密、发件人、收件人及投递错误。

## 3. 后台可配置什么

| 页面 | 当前能力 |
|---|---|
| 系统设置 | SMTP、发信邮箱、拟用服务地址、向超管本人发送测试邮件 |
| 人员管理 | 超管创建管理员，冻结、停用、恢复人员 |
| 项目管理 | 超管创建项目与分配管理员；范围管理员添加、移出普通成员 |
| 授权审批 | 超管批准或拒绝新设备和项目授权申请 |
| 设备管理 | 查看设备及邮箱验证状态，超管撤销其他设备 |
| 我的设备 | 查看本人设备，绑定或更换本人邮箱 |
| 操作记录 | 超管全局记录；项目管理员查看获授权项目记录 |

SMTP 密码在数据库中加密保存，读取接口不返回明文。密码框留空保留原值；界面显示“已保存”。发信设置保存后立即用于后续邮件。设置使用版本检查，避免两个页面互相覆盖。

**保存服务地址不会自动配置 DNS、证书或 Nginx。** 当前实际部署地址为 `https://47.109.23.86:18180`；更换地址需部署端配合更新。新域名、IP、协议或端口构成新的浏览器存储来源，首次访问会被视为新设备；保留当前可信浏览器入口，供超管批准该设备。

## 4. 管理员与项目授权顺序

1. 超管创建管理员账号，邮箱必填。
2. 管理员用自己的浏览器登录，完成邮箱验证；超管批准设备。
3. 超管创建项目，分配已验证的项目管理员。
4. 超管给管理员设备签发该项目的能力和有效期。
5. 管理员可以在该项目添加普通成员、申请成员授权；批准和签发仍由超管完成。

普通成员可以不绑定邮箱；新设备仍必须由超管审批。绑定邮箱后，每台新设备还需要邮件验证。恢复成员关系或账号状态不会恢复旧项目授权，仍需重新签发。

更换邮箱需要当前密码和新邮箱验证码。成功后，其他设备必须重新验证邮箱，已有项目授权和旧会话失效；当前设备获得新的平台会话。

浏览器设备密钥以不可导出形式保存在 IndexedDB，会话凭证仅存内存。刷新页面需要重新输入账号密码，已批准的同一浏览器设备无需重复审批。清除网站数据或更换浏览器会产生新设备。

## 6. 桌面端首次登录

解压 Windows 测试包，双击 `Agent Hub.exe`，地址使用 `https://47.109.23.86:18180`。桌面端与浏览器使用不同的设备身份；即使账号相同，首次使用桌面端也必须完成对应邮箱验证和超管审批。

审批请使用此前已经可信的浏览器设备。原 `http://127.0.0.1:18765` SSH 转发入口继续保留；如果公网地址尚未获批，可以先从原入口登录并批准桌面设备。新建浏览器配置、清除原网站数据、停止 SSH 转发都会影响这一旧入口的使用，不能把新浏览器当作原可信设备。

项目成员登录成功后还需获得面向本设备的项目授权。超管签发时勾选 `project:read`；需要上报进度时增加 `tasks:write`。桌面端点击“刷新授权与连接”，再在“项目与 MCP”中选择目录绑定。
