# 增量经验、阅读预算与 Hindsight 对照

日期：2026-11-10。服务端 0.17.0、Windows 0.19.0，数据库结构保持 0026。发布与验证结果以本文末尾记录为准。

## 1. 用户实际得到什么

工作日志和共享文档继续保留原文。后台按增量资料提取卡片；超管配置兼容 OpenAI 的服务并逐仓库开启后，服务器生成长期知识候选，独立审核后才能进入正式经验。模型密钥只留在服务器。

Agent 开工先读规则、职责和有上限的开工包。遇到具体问题，再通过 MCP 读取相关经验，不把一年、两年的全部日志放进每次对话。同一个对话读过的同版本经验，只返回变化；新的对话仍加载必要内容。

| 内容 | 保存位置 | 如何读取 |
|---|---|---|
| 原始日志、文档版本、审核记录 | 服务器 PostgreSQL；代码及文档提交仍在 Git | 当前授权下按 ID 追溯、分页展开 |
| 记忆卡片、长期知识、向量索引 | 服务器 PostgreSQL 与已有 pgvector | 精确 ID、关键词、语义混合检索 |
| 本运行的职责、经验和已读版本 | PC 系统加密存储 | 联网复核来源、租约与权限后加载 |
| 保护规则与任务专注范围 | 服务器规则与已确认上下文 | 修改前单独核验；经验不能覆盖 |
| Hindsight 对照资料 | 可选的私有实验服务 | 运维 CLI，冻结语料，独立 bank |

不需要在成员电脑新增数据库、Docker 或模型服务。本版沿用现有 pgvector，没有新增生产向量数据库。

## 2. Agent 的操作顺序

1. 检查版本与项目身份，认领任务。
2. `hub_prepare_work` 获取职责、硬规则、范围、交接摘要及记忆缺口，阅读后 `hub_acknowledge_work`。
3. 为当前对话生成一个 UUID `memory_session_id`。用 `hub_recall_experience` 提交任务、运行、租约代数、上下文 ID 和具体问题；已知经验档案号时，使用 `experience_ids` 中的 UUID 精确读取。
4. 阅读返回项的正文、来源、修订、`retrieval` 和 `gaps`。需要核对原始记录时，以 `source_card_id` 调用 `hub_read_memory_source` 分段读取。
5. 后续调用传入上次真正读过的 `delivery.receipt` 作为 `after_receipt`；同一会话已读的同版本正文会省略。没有回执就重发，不能假设丢失响应已被阅读。
6. 新对话或上下文压缩后换新的会话 ID。基础包可通过 `hub_load_memory` 恢复；只有当前会话确实仍保有该包时才提供 `known_content_hash`。
7. 修改前仍执行路径与规则检查；每轮代码变更保存工作记录和检查点。阅读经验不代替日志、评审或代码备份。

`EXP-<UUID>` 是已经存在的正式知识 ID 的可读形式，不是另建一份内容。`SRC-<UUID>` 表示来源卡片。后台长期知识列表显示 EXP 编号，可用于精确查找。

## 3. 阅读预算和实际限制

| 项目 | 当前约束 |
|---|---|
| 单次正文与响应 | 默认 2048 参考单位，可设 1024–4096；默认最多 6 项，最多 12 项 |
| 计量范围 | 完整紧凑 JSON，含正文、来源、修订、回执、诊断和度量本身；另限 24,000 字节 |
| 分词 | 校验过的固定 `cl100k_base` 表；不是所有宿主的实际分词或账单 |
| 分词降级 | 表缺失或哈希不符时用 UTF-8 字节保守计量，明确报告；运行时不下载 |
| 累计限额 | 本机同一运行代次约 24,000 单位，接近上限时停止新增经验正文 |
| 缓存规模 | 同运行最多 32 个来源版本、8 个会话；只存在加密存储 |
| MCP 输出 | 经验正文只输出一次，避免文本和结构化结果各重复一份 |

累计包含普通经验响应的元数据；后台来源核验和额度耗尽后的控制提示不计入新增经验。重新准备同一运行不清零累计量。它不是云端跨设备总额度，也不限制其他原文／检索工具或宿主保有的历史。项目原有的真实用量上报与额度机制仍独立执行。

超过预算的单项会省略，不能让第一条大经验直接超额返回。`omitted`、`has_more` 或缺口出现时，应收窄问题或展开来源。没有命中不证明没有历史。检索模式记录语义检索和关键词降级状态；索引覆盖与队列仍用 `hub_get_memory_status` 查看。

本版能验证响应确实缩小，尚未测量跨宿主账单减少比例。不会宣称固定节省百分比。

## 4. 权限、自净与并发

入口要求本人有效任务租约和已经确认的上下文，沿用仓库范围、RLS、当前文档／日志来源及知识审核状态。语义查询需要联网时先释放数据库事务，返回后重新鉴权。普通用户不能通过经验 ID 读到其他仓库的记录。

追加经验不会静默改写已确认规则包。后续受管检查会重新核验缓存经验的当前修订与来源；撤回、冲突、旧来源或权限变化会清理本地记忆并要求重新准备。账号退出、设备撤销、范围缩小与任务释放也清理相关缓存。

如果等待响应期间任务已经停止或重新准备，迟到结果会被拒绝，不能恢复旧上下文。日志和代码检查点保全按原收尾协议执行。

“自净”指派生经验退出当前读取、清理缓存并保留可追溯原文。它不保证模型自动发现任意语义矛盾，也不是对已经被人复制出去的资料进行远程擦除。

## 5. Hindsight 的接入位置

生产经验入口固定使用 Agent Hub 原生引擎。本版提供 Hindsight 的隔离对照适配器，尚未部署真实 Hindsight 实例或执行真实模型质量对照。

参考上游 [retain](https://github.com/vectorize-io/hindsight/blob/main/skills/hindsight-docs/references/developer/api/retain.md)、[recall](https://github.com/vectorize-io/hindsight/blob/main/skills/hindsight-docs/references/developer/api/recall.md) 与 [operations](https://github.com/vectorize-io/hindsight/blob/main/skills/hindsight-docs/references/developer/api/operations.md)。协议核对日期为本文日期；正式联调需固定上游版本和镜像摘要。

对照有以下限制：

- 仅访问私有 `http://hindsight:8888` 或回环地址，禁止重定向和环境代理，不开放新的公网服务。
- bank 由项目、仓库、受众和冻结语料哈希派生，只允许 `hub-eval-...`；不使用默认共享 bank。
- 仅导入人工授权导出的资料或合成样本；示例不含业务代码、凭证或真实工作日志。
- 入库会触发上游提取模型调用，必须显式开启；没有自动重试。稳定文档 ID 和操作 ID 用于避免重复。
- 召回按当前白名单使用严格 tags，只接受当前获准来源的 ID 顺序；旧修订、混合来源和外部来源被丢弃。上游生成正文不返回 Agent。
- 上游异步任务必须完成才运行对照；入队成功不算索引完成，更不证明召回质量。

### 运维操作

随源码提供合成样本 `projects/agent-hub/examples/experience-comparison.synthetic.json`。操作在服务器受控环境中执行，Hindsight 模型、API Key 和网络由运维单独配置；不是在成员电脑安装服务。CLI 不读取生产数据库，也不会修改生产引擎。

```sh
agent-hub compare-experience-engines \
  examples/experience-comparison.synthetic.json /secure/eval/ingest-001.json \
  --ingest --allow-model-calls

# 等上游任务完成，以入库报告中的 operation_id 再执行：
agent-hub compare-experience-engines \
  examples/experience-comparison.synthetic.json /secure/eval/recall-001.json \
  --operation-id <completed-operation-uuid>
```

每次报告使用新的文件名，输出文件已存在时不再发起模型调用。失败保留简短错误记录；不自动重复付费调用。Hindsight 认证密钥由进程环境 `HUB_HINDSIGHT_API_KEY` 提供，不作为命令参数或报告正文。

报告只含语料／问题哈希、来源数量、命中、召回率和耗时，不含原始问题、经验正文或密钥。样本里的 `native_ids` 是人工冻结的基线排序，报告明确标记 `fixture-reported-order`；未提供时标记没有基线，不能冒充在线实测。费用与真实模型用量未知时明确写未知。

真实对照还需固定模型和 Hindsight 版本，准备有人工答案的授权样本，并记录原生在线排序、账单用量、错误率及延迟。结果满足要求后再决定是否引入生产；当前协议测试使用模拟上游，不能当作实际质量结果。
