# 实施计划与验收

> v0.4｜2026-11-06｜本文件是完整平台的验收基准。身份、后台和 Windows 桌面/MCP 子流程已有实际测试，见[实施记录](06_实施记录.md)；其余未标记通过的用例仍待执行。
>
> 最新顺序见[生产实施基线](14_跨端协作Skill框架_生产实施基线.md)第 14 节：资源/任务执行骨架 → 逐轮记录与快照 → Skill/记忆 → Git/更新/回收 → 实机与生产验收。任务身份和原子认领提前，不能等记忆系统建好再补。该文 P01—P16 与本文 A/F/M 用例一同构成验收范围。下列旧阶段保留作交付分类；“跨项目”需区分组内跨子项目和跨协作空间访问。

## 1. 阶段与交付

| 阶段 | 交付 | 完成标准 |
|---|---|---|
| P0 设计 | 本组设计、数据模型、接口与验收清单 | 需求映射完整；关键状态和权威来源明确 |
| P1 身份与项目 | 管理端基础、超管初始化、人员、项目、审批、设备、邮箱 | 管理员和项目只能由超管创建；设备与授权审批用例通过 |
| P2 文档与存储 | PostgreSQL 迁移、项目 Git 接入、文档索引、受限 MCP 查询 | 项目隔离与版本化读取通过；中文查询基准可复现 |
| P3 任务协作 | 拆解、认领、检查点、交接、提交、审查状态 | 并发只有一个主执行者；旧代次提交被拒绝 |
| P4 框架客户端 | 安装 Skill、日常 Skill、部署清单、桥接器、快照及完整退出 | 上传回执后清理；失败可恢复；脚本自身能够清理 |
| P5 适配与部署 | 七种 harness 的双系统配置、发行包、Docker 部署和恢复手册 | 目标组合逐一验收；完成备份恢复和真实双设备接力 |

源码可在本机开发。按用户最新要求，数据库、Docker 与数据库测试统一在指定服务器运行；当前数据库部署及实机核验见[服务器部署记录](07_服务器部署.md)。

## 2. 需求验收

| 用例 | 对应需求 | 操作与预期 |
|---|---|---|
| A01 | R01 | A 项目成员用 B 的 ID 搜索、读取、下载、认领和导出，全部拒绝且不泄露 B 元数据 |
| A02 | R02 | 超管查询并改变账号、设备和成员状态；受影响的新请求与续期立即按新状态处理 |
| A03 | R03 | 项目管理员、普通用户、匿名注册都不能创建管理员；超管创建成功 |
| A04 | R04 | 非超管创建项目被拒绝；超管可创建并分配管理员 |
| A05 | R05 | A 管理员不能管理 B 成员或其他管理员；项目范围来自服务器 |
| A06 | R06 | 管理员签发申请在待审批状态无访问能力；超管批准后只发放精确批准范围；修改申请使旧批准失效 |
| A07 | R07 | 首次授权、扩权、新设备都等待审批；已批准会话自动续期；撤销后对应普通权限不可续期 |
| A08 | R08 | 未验证邮箱的管理员不能激活；普通成员可不绑定邮箱；绑定与更换需要验证 |
| A09 | R09 | 有邮箱新设备两项都满足才通过；无邮箱设备须超管审批；仅复制访问/刷新 Token 而无设备私钥不能使用 |
| A10 | R10 | 两个账号或同人两设备同时认领同任务，仅一方成功；交接有检查点并使旧 fence 失效 |
| A11 | R11 | Git 文档入库可检索并返回 SHA/哈希；索引删除后可重建；任务状态不被旧 Markdown 覆盖 |
| A12 | R12 | 成员被移除后普通 MCP 操作返回退出指令；只允许本人设备的限定收尾动作 |
| A13 | R13 | 清单中的框架文档、规则、Skill、脚本、框架测试和配置归属项均处理，包含卸载脚本自身 |
| A14 | R14 | 分块上传中断、网络不可用、回执未就绪时不提前清理；恢复后幂等续传并退出 |
| A15 | R15 | Windows/macOS × 七种 harness 分别完成安装、设备验证、认领、交接、撤权、上传与卸载 |
| A16 | R16 | 指定服务器 Docker 主库和制品持久化、数据库端口不公开、备份恢复通过；本机没有数据库部署 |

| M03 | R19 | 有 Web、PC 两仓权限但处于 Web 专注模式，拆解、认领和受管交付均不能自行新增 PC 工作；解除专注仍不扩权 |
| M04 | R20 | 原文可恢复，知识卡片有来源版本；撤回或取代决定能使相关摘要失效，旧内容仍可追溯 |

| M06 | R22 | 未提交工作有服务端有效快照回执，移除原成员后接手人用自己的设备身份恢复任务、代码、依据和下一步 |

| M09 | R25 | 开始/恢复对话检测已批准适用发行版；桌面、框架、适配器及协议分别核验；更新失败保留工作和补传入口，不能只升级桌面即宣称框架已更新 |

## 3. 关键故障与对抗性验收

这些用例验证真实状态和产物，不以匹配日志措辞或存在某个函数代替。

| 用例 | 场景 | 预期 |
|---|---|---|
| F01 | 认领请求提交成功但响应丢失，客户端重试 | 同幂等键返回原结果，无第二个 attempt |
| F02 | 任务提交与成员撤销同时发生 | 事务顺序明确；撤销之后不能提交普通结果 |
| F03 | 租约过期，旧执行者恢复 | 新执行者 fence 更高，旧执行者不能覆盖 |
| F04 | 不同任务声明相同写范围 | 按项目策略拒绝或协调，不同时授予互斥写权 |
| F05 | 连接池连续服务不同项目用户 | 不残留上一事务权限；直接数据库访问测试 RLS |
| F06 | 提供其他项目的文档 ID、制品 ID 或下载游标 | 统一不可访问结果，无项目内容和存在性泄漏 |
| F07 | Token 请求的审批内容在批准后被篡改 | 哈希或版本校验拒绝签发 |
| F08 | 访问令牌仍未过期，但人员资格刚撤销 | 后续请求拒绝，不能等自然过期 |
| F09 | 原项目 Git 写权限已撤销 | 工作仍能通过专用收尾通道上传 |
| F10 | 快照分块齐全但最终校验或持久化失败 | 不产生有效回执，不进入清理 |
| F11 | 旧快照回执对应不上当前新增工作 | 重新快照上传，禁止凭旧回执清理 |
| F12 | 上传包有路径穿越、链接或异常展开规模 | 拒绝或隔离，不能执行包内代码或覆盖服务文件 |
| F13 | 本地清单路径被替换为父目录、链接或 Windows junction | 清理拒绝范围外目标，保留可恢复结果 |
| F14 | 用户配置有框架之外的改动和其他项目引用 | 只处理有归属的项；冲突记录待处理；其他项目正常使用 |
| F15 | Windows 锁定文件、macOS 权限拒绝 | 逐项记为待清理，恢复后继续；不伪报 removed |
| F16 | 清理执行过程中再次收到相同退出指令 | 同作业幂等继续，不重复上传或跨代次删除 |
| F17 | 项目恢复授权或重新安装，旧清理任务延迟运行 | 部署 ID/代次不匹配时停止，不能清理新部署 |
| F18 | 账号或设备已全局禁用，普通认证拒绝 | 原登记设备仅能用既有收尾能力恢复对应退出作业 |
| F19 | 邮件失败、验证码重放、请求撞库或设备伪造 | 不批准设备；验证码限流、单次消费及设备证明生效 |
| F20 | Worker 在 DB 提交后、Git 归档前崩溃 | outbox 重试，无状态丢失或重复归档 |
| F21 | 整机备份恢复 | 人员、授权、任务、制品与回执可恢复；设备缓存不被当作权威来源 |
| F22 | 所有可信超管设备丢失 | 本地恢复流程可用，项目管理员不能冒充超管批准新设备 |

## 5. 部署前需要的信息

| 信息 | 用途 | 何时提供或核对 |
|---|---|---|
| 目标服务器、可用磁盘、Docker 状态 | 应用、数据库与制品部署 | 开始实施部署时核对 |

敏感配置通过目标环境的受控配置注入。设计、Skill、接口示例与 Git 不保存服务器密码、SMTP 密码或数据库连接密码。
