# 多项目 Agent 协作平台：设计总览

> 版本：v0.8｜日期：2026-11-06（Asia/Shanghai）｜状态：身份、管理后台、进度及 GitHub 文档索引已部署，Windows 桌面/MCP 已提供；完整平台尚未验收。最新统一方案见[跨端协作 Skill 框架：生产实施基线](14_跨端协作Skill框架_生产实施基线.md)，记忆细节见[授权组装、分层记忆与交接](13_授权组装_分层记忆与交接方案.md)，现有实现差异见[系统复查](12_项目组语义与系统复查.md)。
> 本组文档将对话中已确认的要求转为可实现、可验收的设计；技术选择和默认参数属于设计建议。

## 1. 目标

在 Windows、macOS 上，让不同 harness 使用同一套项目知识、任务和权限服务。架构师拆解任务，执行者认领和开发，其他设备能够接手或审查。Markdown 保留可读的项目材料，Git 记录版本，数据库处理实时协作状态，MCP 提供统一入口。

首版采用各设备本地运行 harness、中央服务管理协作状态的形态。退出处理由 Agent 指令与按需运行的脚本配合，在调用 MCP 发现状态变化时触发。

用户在平台创建的一个“项目”可以是一项独立工程，也可以是包含多个子项目、多个仓库的项目组。原 `install.md` 负责在这样的工作区建立共同入口、角色、知识及跨子项目流程。组内按任务范围协同，跨协作空间仍需相应授权。后续拟保留现有 `project_id` 作为顶层协作空间标识，再补子项目和仓库映射；当前代码尚未实现这些关系。

按用户后续澄清，框架 Skill 使用独立仓库，各工程也分别存放在独立仓库；成员按批准资源在本机组装项目组。业务共享日志另行授权，开工先恢复有关历史与增量，形成本地精简记忆。专注模式同时约束工程、目标端、修改和功能范围。原文长期保留，记忆持续提炼，向量检索拟采用现有服务器 PostgreSQL 的 pgvector；这些新增能力均待实施。

## 4. 主要设计决定

| 决定 | 方案 | 原因 |
|---|---|---|
| D01 | 服务器主库采用 PostgreSQL | 集中管理授权、审批、任务事务和操作记录；便于项目隔离 |
| D02 | 正式文档原件在 Git；新工作记录由服务器追加保存并导出 Markdown；数据库保存索引、派生记忆和实时状态 | 各数据来源明确；原文与交接记录可恢复，任务认领不依赖 Git 合并结果 |
| D03 | Skill 和各工程分别使用独立仓库，按本人授权组装项目组；业务资料另行授权 | 仓库访问边界实际生效，组内仍可按授权协作；当前一项目一文档源仍需迁移 |
| D04 | 服务端采用模块化单体，API、MCP 和后台作业共享业务逻辑 | 第一版保持部署规模可控，防止不同入口使用不同权限规则 |
| D05 | 设备采用本地桥接器、设备密钥与按需脚本 | 统一设备验证、凭证保管、上传和清理；不要求各 harness 自带相同功能 |
| D06 | 授权立即撤销，收尾通道独立存在 | 允许回收未交付工作，同时阻止继续读取与开发 |
| D07 | 安装和卸载使用同一份部署清单 | 完整记录框架产物、配置片段、共享依赖和卸载脚本自身 |
| D08 | 用户、设备、会话、角色、执行实例分别建模 | 同一人多设备不会被误当作同一次任务执行 |
| D09 | 原文、知识卡片、模块记忆、任务检查点、本地执行记忆分层 | 持续增量处理，开工按需恢复并可追溯原文，防止摘要逐层失真 |
| D10 | 现有服务器 PostgreSQL 增加 pgvector，结合关键词和必要资料关联检索 | 先复用存储及运维，实测中文、权限过滤、召回和总成本后再决定扩大架构 |
| D11 | 原子任务/执行身份先落地，再实现逐轮事实采集、简短笔记和快照回执；Skill 按真实能力契约发行 | 确保工作归属、代码与说明可核验，不用提示词替代运行机制 |
| D12 | 受管生产路径补齐 Git 访问和交付控制，直连 Git 模式单独披露授撤权边界 | MCP 停权不会自动撤销外部 Git 凭证；旧执行代次不能绕过协作状态直接交付 |

选择 PostgreSQL 是基于完整的多人协作要求，而非文档检索规模。SQLite 可用于客户端恢复日志或缓存，但不是服务器的必需依赖。选型依据见系统架构的来源说明。

## 5. 是否需要先提供数据库

**当前已在用户指定服务器准备数据库，无需另外提供数据库。凭证只保存在服务器。**

实现和部署阶段有两条路径，使用同一份数据模型：

- 新部署：在目标服务器通过 Docker 创建 PostgreSQL、应用和持久化存储。
- 复用现有 PostgreSQL：使用独立数据库或独立受控命名空间、独立运行账号和迁移账号。

数据库不对客户端公开。客户端只访问 HTTPS 服务，Git 使用项目级权限。数据库凭证由服务器配置注入，不进入仓库、Skill、Markdown 或客户端 MCP 配置。

## 6. 数据的权威来源

| 数据 | 权威来源 | 其他副本 |
|---|---|---|
| 正式需求、设计、职责、知识、经验文档 | 项目组所登记仓库指定分支的 Markdown 版本 | 服务器按提交归档的原文、设备副本、数据库索引 |
| 平台接收的共享工作记录与交接事件 | PostgreSQL 的追加原文及结构化记录 | Markdown 导出和业务知识仓库中的归档副本 |
| 派生知识卡片、模块摘要、检索向量 | 带来源及生成版本的数据库记录，可从原文重建 | 本地按授权和任务生成的精简记忆 |
| 人员状态、项目成员、审批和授权 | PostgreSQL | 后台界面和受限查询结果 |
| 任务状态、认领、执行代次、租约 | PostgreSQL | Git 中生成的状态快照和工作日志 |
| 未交付工作快照 | 经验证的服务端制品及其接收记录 | 后续由管理员审核并整理到 Git |
| 专注范围、临时计划、本机路径 | 按执行上下文保存；任务专注范围随检查点接续 | 不同步为全体成员共用的全局开关；本机路径按新设备重新映射 |
| 框架安装归属 | 本地部署清单与服务端清单摘要 | 安装回执、退出作业 |

文档索引可以重建。人员授权、执行状态、退出作业和制品接收记录必须备份，不能以扫描 Markdown 代替恢复。
