# 授权范围内的语义与关键词混合检索

日期：2026-11-09。已发布：服务端 0.13.0 / 迁移 0016，桌面端 0.15.0。机器可读结果见[本批验收记录](审计数据/2026-11-09_授权语义检索验收.json)。

## 使用

`hub_prepare_work` 自动加载当前获准交接、经审核知识和来源，结合语义和关键词，无须配置云模型密钥。PC、Web“共享记忆”可输入问题，或切换“仅关键词”查代码标识符。MCP 的 `hub_search_memory`、`hub_search_knowledge` 支持 `search_mode: hybrid | keyword`。

状态显示当前授权范围的索引覆盖和失败队列。日志先共享，再异步提取、编码；已共享不代表向量已更新。索引滞后或模型故障时显示缺口，按需展开原文。无召回不代表没有历史。

## 数据与模型

- 复用服务器 PostgreSQL 18.6 / pgvector 0.8.7，本机不安装数据库、Docker。
- 原文、文档版本和知识审核事件保留，向量是可重建索引。
- BAAI/bge-small-zh-v1.5 的 Xenova ONNX FP32 转换，512 维。固定转换提交、Tokenizer、模型 SHA-256，见 `projects/agent-hub-embedding/model-manifest.json`。
- 查询加官方检索前缀。CLS 归一化，长文本按 384 Token 窗口、320 步长全部编码，平均后再归一化，不静默截断尾部。每次最多 32 窗口。
- 模型、权重、分块算法共同定义 `bge-small-zh-v1.5-fp32-75c43b0-cls-mean384s320-v1`。升级使用新 ID 和作业，禁止混向量。

## 增量与权限

卡片插入、知识审核进入 active 时，同一事务排入 `embedding_jobs`。0016 为旧摘录及已生效知识补排；待审知识不编码。

专用 `hub_embedding_worker` 只读取摘录、知识及派生索引，不读取原始日志、身份表或 Git 凭证。短事务认领 45 秒作业租约，事务外推理，新事务核对租约、内容摘要和知识状态后写入。失败按 30/60 秒退避，第三次失败由有权管理员重试；进程中断的过期租约可接手。推理期间知识退役则丢弃结果。

查询先验证身份和项目，释放事务进行编码，再重新鉴权和核对任务。查询期间被移除者不能读取结果。DPoP 在同一 HTTP 请求仅验签并记 nonce 一次，重新鉴权沿用本请求已验证的 Token 和设备指纹，不接收客户端向量。

卡片、知识、向量和队列继承原文 RLS；仓库筛选继续收窄。来源配置变化、删除或撤权在读取时立即生效，不等待向量删除。不存在全局向量结果跨用户缓存。

## 检索与成本

1. 在当前可读项目、仓库和有效状态集合内做精确余弦距离搜索，不使用全局 ANN 先召回再过滤。
2. 模型 ID、512 维及内容 SHA-256 一致才参与。关键词独立召回，保留中文片段和标识符。
3. 两路各取最多 240 候选，用 RRF（k=60）融合；同任务交接优先。分页限于候选池，达到上限时报告，需收窄问题，不宣称遍历全部历史。
4. 排序只表示相对相关性，不是概率、事实、审核或语义冲突判断。
5. 开工新日志、知识、摘录共用 12,000 UTF-8 字节预算；向量不返回 Agent。`coverage`、`retrieval`、`gaps` 报告索引和降级。模型 Token 账单仍只能由调用方报告；本服务的编码不调用生成模型 API。

## 部署与恢复

模型容器仅连 internal Docker 网络，不公开端口、不持有数据库或登录凭证，无外网、不记正文日志、关闭遥测。非 root、只读文件系统、384 MB、0.7 CPU，单推理槽、最多 8 个连接。额外 Worker 限制 192 MB / 0.3 CPU。故障不阻止日志保存。

首次运行 `deploy/provision-embedding-worker.sh`，再应用 0016。部署阶段用 `fetch-model.py` 下载核验权重；运行不下载或加载远程代码。挂载模型清单必须与镜像内清单一致。

数据库备份含向量和作业；恢复审计核对维度、内容摘要。固定权重可重下载；离线恢复还需备份模型目录和镜像。运维巡检检查模型健康、Worker 运行及失败/滞后队列。

## 边界

本批提供真实本地编码和 pgvector 混合检索。不会自动生成或批准长期结论、理解任意矛盾、授予权限或解除禁改规则。大型项目 ANN、多模型在线迁移、跨宿主调度、持续异地备份及外部告警仍需后续开发和真实环境验证。

## 验收结果

### 模型选择与质量范围

在 10 篇合成资料、12 个中文及代码标识符查询上，Q8 的 Top3 为 10/12，未达到本批预设的 90% 门槛，因此正式部署 FP32。FP32 的 Top1 为 9/12、Top3 为 11/12，最差排名为 4；隔离受限 CPU 测试的单查询约 8–41 ms，峰值 RSS 182.9 MiB。长输入实际分为 6 个窗口，输出 512 维。全部查询和排名保存在验收 JSON。

这组小样本只用于本批模型取舍。不能据此保证一年或两年业务历史的召回率、多人负载下的延迟，或认定“没有搜到”就是“没有记录”。精确搜索的成本随当前可读向量数量增长，大规模容量和效果仍待实测。

### 代码、授权与真实联调

后端 215 项、桌面 126 项测试通过，覆盖中文同义查询、标识符关键词、待审知识不编码、审核后索引、失败退避、过期租约恢复、推理期间知识退役、索引覆盖及明确降级。模型 ID、维度、NaN、零向量、过大响应、重定向和网络异常均有拒绝或降级验证。

真实 Windows Controller → DPoP HTTP → 服务器隔离 PostgreSQL、摘录 Worker、Embedding Worker 和 FP32 服务联调通过。开工包可同时加载同事交接、文档和已审核长期约定；新日志保留长期知识，来源失效阻断旧上下文并清除本机投影。成员在查询编码期间被移除时，返回阶段重新鉴权并拒绝；跨仓库的原文、向量及队列统计继续由 RLS 隔离。撤权收尾上传、受管框架卸载和业务代码保全继续通过。

联调使用一台物理 Windows、四个逻辑身份/设备，不代表跨操作系统实机或真实团队验收。Web 与 Electron 的界面验证使用真实浏览器、模拟后端，覆盖检索模式、索引覆盖、来源展开及无横向溢出；服务端权限由独立真实联调验证。

联调最终开工记忆为 4,099 UTF-8 字节，预算为 12,000 字节。未测量模型计费 Token 或长期节省率，不能把字节数当作 Token 消耗。服务器编码不调用生成模型 API；本地 Agent 的提炼与开发仍会使用其自身上下文及模型额度。

### 升级、恢复与正式部署

0015 → 0016 非空升级保留旧活跃任务、原始日志、卡片、已确认上下文、长期知识及审核事件，并为旧卡片和生效知识补生成 2 条真实向量。隔离库的非空 dump/restore 包含 1 个文档原件、5 张卡片、2 条知识、5 次决定和 7 条真实向量；恢复前后的向量值及内容标识摘要一致，来源审计通过。

正式数据库仍只在服务器运行，保留 `agent-hub-postgres-data`，端口未公开；Embedding 服务只有内部网络。独立编码 Worker 无 superuser、BYPASSRLS、建库或建角色权限，运行账号不是其成员。派生表强制 RLS 核验通过。正式备份、0016 恢复演练、来源审计和最终巡检通过；模型目录也进入备份，恢复核验各文件哈希。正式平台当前为 0 个业务项目、0 条业务向量，不能把隔离库的非空恢复当作实际业务恢复证明。

首次切换曾因模型首个健康探针尚未执行而提前失败并恢复旧应用，同时发现发布目录指针没有随旧应用恢复的问题。本批发布步骤已补等待健康检查及指针恢复；模型就绪后完成正式切换，再完成备份、恢复和巡检。本批 5 个隔离测试容器、2 个带标签网络及明确核验的匿名测试卷已清理，正式卷保留。

Windows EXE、ZIP 与 metadata_version 16 的 Ed25519 签名更新清单已发布；隔离旧客户端通过公网从 0.14.0 在线升级并重启到 0.15.0。本机一体安装完成，163 个程序文件与签名清单一致，10 个受管 Skill 文件与包内版本一致；从实际 Codex 配置启动 stdio MCP，确认版本 0.15.0、签名更新源及登录门禁。用户仍需本人登录，没有替用户验证身份。EXE 尚无 Authenticode 签名。入口文档保留原 `install.md` 主体，以当前 Skill 和安装入口指导使用。

本批未开展用户暂缓的业务试点，也未完成 macOS、全部宿主逐轮钩子、跨宿主调度、长期规模检索、持续异地备份或外部告警验收，不能认定总体生产验收已完成。
