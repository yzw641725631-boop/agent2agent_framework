# 双仓库协作与断网恢复联调

2026-11-11｜对应[原计划第11节](21_完整需求复核_GitHub对照与Token预算.md#11-继续整改的顺序与验收)阶段D“Agent协作与跨端”，并覆盖阶段B的可靠交接。服务端0.22.0 / schema 0032、Windows 0.23.1。

## 本轮范围

按用户“暂时没有第二台电脑，先完成现有环境联调”的安排，使用一台Windows电脑、两个合成普通成员和两个独立设备身份，运行真实桌面Controller、stdio MCP子进程、DPoP HTTP与服务器47隔离PostgreSQL。Web和API使用两个合成仓库，未接入真实业务或生成模型。

Windows加密使用Electron 45.2.3的系统安全存储。两个账户各有独立加密Vault、检查点目录和Git工作目录；重启阶段销毁原Controller并关闭桥接子进程，再从磁盘解锁Vault、重新启动Controller与MCP桥接。

这里的重启范围是桌面运行组件和桥接子进程；没有终止整个Electron应用进程或重启操作系统。

后续[43号验收](43_桌面进程退出与崩溃恢复验收.md)补齐不同Electron主进程之间的正常退出与强制终止恢复。本文仍保留本轮原有测量范围。

Codex与Claude Code的生命周期请求由测试驱动注入实际桥接入口。没有启动这两个产品，也没有进行人工或模型代码评审；评审、测试的验证对象是不同身份的权限、流程顺序和持久记录。

## 实际联调结果

完整流程16项检查通过，原始时间、耗时、检查项及日志/代码独立回执摘要见[验收数据](审计数据/2026-11-11_双仓库协作与断网恢复联调.json)。

| 环节 | 验证结果 |
| --- | --- |
| 跨仓库依赖 | Web未完成时API认领被拒；Web完成后API可接受投递并执行 |
| 派工与原子认领 | receive不产生租约；accept返回对应实例的运行；相同操作重试保持同一运行，其他执行者不能双领 |
| 固定MCP范围 | API连接不能读取Web任务；无对应仓库授权的成员不能读取交接日志 |
| 两种宿主协议 | 通过真实生命周期桥接入口检查未绑定任务、越界、保护目录和允许路径；记录为协议联调 |
| 断网待传 | 注入传输中断后，MCP保存Windows加密检查点，返回pending，日志共享和代码备份回执均为false |
| 重启补传 | 重新加载加密Vault和待发文件后补传；日志与代码分别获确认，同操作重试不重复生成记录 |
| 同事接手 | 另一身份取回并导出未提交文字、二进制和删除记录到新目录；原有工作目录文件保留 |
| 正式流程 | 两仓分别提交、评审、测试、发布；作者自审被拒，另一成员执行评审/测试门控；提交后的旧运行不能继续修改 |
| 推送与重连 | 实际桌面SSE订阅断开后，按已保存游标重新连接，补齐期间新增事件，事件序号不重复；两仓提交有持久活动记录 |
| 撤权与数据保留 | 作者撤权后旧MCP调用被拒，另一获准成员仍能读取已共享交接，业务工作文件保留 |
| 提示词边界 | 注入事件中的提示词标记未进入解锁后的桌面Vault |

服务器HTTP夹具限定在`hub_test`、`hub_owner`和显式`HUB_TEST_HTTP=collaboration-only`。种子接口含合成设备凭证，另需随机`HUB_TEST_FIXTURE_KEY`，无密钥返回404；服务仅映射服务器`127.0.0.1:18768`，通过SSH隧道连接。夹具容器限制512 MiB内存、1.5 CPU、无swap。

测试结束后停止本轮夹具，恢复测试数据库原先的停止状态。正式发行目录、数据库0032、生产卷`agent-hub-postgres-data`与网关健康另行核对。

## 复现入口

- 服务端夹具：[collaboration_http_fixture.py](../projects/agent-hub/tests/collaboration_http_fixture.py)。只在服务器隔离测试网络运行；与其他会清空`hub_test`的测试串行执行。所用服务端源码必须与被测版本一致。
- 桌面驱动：[collaboration.integration.cjs](../projects/agent-hub-desktop/tests/collaboration.integration.cjs)。调用真实Controller、加密Vault、Git、桥接子进程和HTTP；每次需重置隔离夹具，使用新生成的种子身份。
- Windows入口：[check-collaboration.cjs](../projects/agent-hub-desktop/scripts/check-collaboration.cjs)。通过Electron运行，设置`HUB_TEST_HTTP=collaboration-only`、私有`HUB_TEST_FIXTURE_KEY`及绝对路径`HUB_COLLABORATION_REPORT`；清除`ELECTRON_RUN_AS_NODE`。报告文件必须尚不存在，输出不含种子身份和凭证。

服务器注入专用测试库角色密码与随机夹具密钥，设置`HUB_ENVIRONMENT=test`、`HUB_MAIL_MODE=memory`和`PYTHONPATH=/app/src`。夹具使用`postgres:5432/hub_test`；该别名必须只解析到隔离测试库。内网数据库网络不发布HTTP端口，需要额外连接仅映射回环地址的测试网络。不要将夹具接入正式数据库网络，也不要在Windows启动数据库或Docker。

夹具密钥与测试环境文件只保存在受控位置，不进入仓库、命令参数或报告。SSH隧道就绪后，在`projects/agent-hub-desktop`目录执行：

```powershell
& .\node_modules\electron\dist\electron.exe .\scripts\check-collaboration.cjs
```

入口创建独立临时Electron用户目录，不加载本人桌面账号。驱动收尾前关闭连接，核验临时目录确实属于本次测试，再清理合成工作目录。
