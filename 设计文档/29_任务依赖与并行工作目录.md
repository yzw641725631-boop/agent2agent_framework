# 任务依赖与并行工作目录

日期：2026-11-09。版本：服务端 0.11.0 / Alembic 0014，Windows 0.13.0。

## 本批解决什么

架构师可以把项目组任务拆成有完成先后的任务；成员与不同 harness 仍使用本人、设备和仓库权限。服务器原子检查前置条件及代码范围占用，桌面端为同机并行工作创建独立 Git worktree 和任务连接。当前职业和记忆继续按执行实例保存。

| 关系或状态 | 行为 |
|---|---|
| parent_id | 层级，父任务完成须等待所有子任务，包括负责人当前不可读的子仓库任务 |
| depends_on | 同项目直接前置，最多 40 项，只有正式 completed 才解锁 |
| 修改依赖 | 首次认领前、需 tasks:publish、任务版本和原因；重新准入，旧决定保留 |
| 循环 | 拒绝直接、间接循环及父任务等待子任务产生的组合死锁 |
| 代码范围 | 同一仓库按不区分大小写的路径前缀检测；不同仓库和不重叠目录可并行 |
| 占用时间 | 有效开发租约，以及 review、testing、release_ready；释放、到期、退回或完成后释放 |
| 本机目录 | 原目录旁 `.agent-hub-worktrees/<task_id>/<run_id>/`，分支 `hub/<task_id>/<run_id>` |
| 固定连接 | 独立工程连接固定项目、仓库、任务和执行实例；准备时阻止同目录出现第二个有效执行实例 |
| 推送检查 | 仅忽略安装收据登记的未跟踪配置及框架文件，已跟踪改动和未知文件仍阻止推送 |

人工资料 declaration 不占代码路径，适合协调父任务；不能当作代码修改证据。范围占用约束受管协议，不是系统文件写入沙箱。已过期的开发者仍可能在外部编辑器写文件，因此必须使用新租约、独立目录和代码审查接手。

## 授权、并发与存储

新增 `task_dependencies` 表，项目与任务使用复合外键、无自引用约束、双端可见的强制 RLS。创建前置关系时必须能读取两端任务；不能通过新关系取得其他仓库代码或日志权限。

不可见前置只返回“前置是否全部完成”和“存在不可见依赖”，不返回其 ID、标题或数量。服务器通过限定 SECURITY DEFINER 布尔函数检查完整图；客户端不依赖被 RLS 过滤后的局部图判断可开工或父任务已完成。更新依赖响应不缓存跨仓库任务标题或前置 ID，避免幂等回放泄露旧权限下的数据。

认领、修改依赖、流程决定继续使用现有按项目串行的事务锁；鉴权在取得锁后重查。并发相互依赖修改只有一个可成功，并发认领重叠代码范围也只有一个可成功。规则增加 B-PARALLEL，现有准备包随规则哈希变化重新确认。

本批不新增数据库服务，继续使用服务器 PostgreSQL；所有数据库测试在服务器隔离容器进行。本机没有部署 PostgreSQL 或 Docker。

## 独立目录与失败保全

先认领，再在准备前调用 `hub_create_task_worktree`。固定目录从原仓库的当前已提交 HEAD 创建，原目录未提交工作保留。不会自动拉取、合并、重置、清空目录、启动 Agent 或转移原修改。前置任务完成不证明 Git 变更已经合并，接手者必须核对交付回执及实际代码基线。

同一操作使用稳定 operation_id 和本机加密档案内的创建收据。中断后核对共同 Git 目录、分支和绑定；目录已有未知文件、链接、来源或分支变化时拒绝自动恢复。检出过滤程序可能执行本机命令，受管创建遇到仓库自定义 smudge/process 时拒绝执行；已存在的合适目录可由用户核验后接入。仓库配置检查同时覆盖 worktree 的独立配置，防止额外 include、地址改写或程序入口绕过。

worktree 共享 Git 对象和部分配置，只隔离工作文件及分支；代码保密仍以独立仓库和仓库授权为边界。撤权仍先上传工作并核对回执，再按该 worktree 连接的安装收据卸载 MCP、职责、脚本和测试。业务代码、Git 工作目录及加密检查点保留，不自动递归删除。

## 使用顺序

1. 负责人创建各仓库的任务，填写路径及 depends_on，在 Web 完成准入。流程与依赖可在 PC 和 Web 查看。
2. 每个执行者用自己的实例在具体仓库认领；阻塞时查看前置与占用，不更换角色或新建实例绕过。
3. 同机并行时创建独立 worktree，在返回目录重新加载开发工具、信任工程，再准备和确认当前职责、规则与记忆。
4. 每轮分别保存任务日志，核对日志共享、代码备份、Git 交付回执。完成后提交检查点，依次评审、测试、发布确认。
5. 同仓库共享接口或同一文件的任务，先拆成契约任务或串行开发；不同文件的真实语义冲突仍由评审和测试发现。

## 实现参考

工作目录实现参照 [Git worktree 官方文档](https://git-scm.com/docs/git-worktree)，事务协调沿用 [PostgreSQL 事务级 advisory lock](https://www.postgresql.org/docs/current/explicit-locking.html#ADVISORY-LOCKS)。目录隔离和数据库协调分别约束本地工作文件与服务端状态，不能替代独立仓库权限。
