# Agent Hub 桌面端

Windows x64 桌面端 0.16.0，新增执行者登记、任务投递回执、逐轮漏记状态及 Codex / Claude Code 钩子配置预览。配套服务端 0.14.0 / 迁移 0017。保留知识审核、任务依赖、独立 worktree、多仓库授权、检查点及撤权交接。无需在电脑安装数据库或 Docker；Git 操作需要本机已有 Git。设计与边界见[语义检索](../../设计文档/31_授权范围内的语义与关键词混合检索.md)。

先读[整体使用指南](../../使用指南.md)。绑定项目组根目录后可选择“组装仓库”，只拉获准代码，每个仓库生成独立连接。PC/Web 的“共享记忆”可切换日志摘录和长期知识；Web 可提交候选、审核和显式替换。Agent 通过 MCP 从原文提炼候选，经审核的有效知识按任务相关性加载，不扫描全部历史。PC“项目与 MCP → 部署职责”可生成七种职业文档、流程与自检脚本。已支持授权范围语义检索。本版新增执行者登记、任务投递回执和首批逐轮钩子；跨宿主自动执行仍待实现。

## 开始使用

从[框架仓库 README](../../README.md)按一句话指令安装。Agent 获取仓库中的安装脚本和发行信息，校验并安装 EXE，然后安装同一发行版的 Skill、合并所选开发工具的用户级 MCP 配置。首批自动配置 Codex、Claude Code、Cursor；实际宿主策略和项目信任仍由开发工具执行。

从框架仓库运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/install-windows.ps1 -Harness codex
```

`codex` 可替换为 `claude` 或 `cursor`。已有程序会先核验再复用；冲突时保留原配置，修复后可重试。Codex 使用自定义 `CODEX_HOME` 时沿用该目录。桌面在线升级只更新程序；首次补齐 Skill 与自动 MCP 配置仍需运行安装入口。

安装完成后，在 PC 端完成本人登录，重新加载开发工具，调用安装连接的 `hub_connection_status`。可以直接要求 Agent 列出项目、让超管创建项目，或用 `hub_connect_project` 将获准项目接入已有本地目录。项目配置生成后重新加载，使用固定项目连接读取文档与上报进度。业务代码需要另行取得仓库权限和拉取，安装器不会克隆业务代码。

以下是单独安装和手工接入方式：

1. 运行当前版本 EXE 完成安装，在桌面或开始菜单打开 Agent Hub。也可通过已有客户端在线升级。
2. 服务器地址使用 `https://47.109.23.86:18180`，输入现有后台账号和密码。
3. 超级管理员使用密码和本设备邮箱验证码自助确认新设备，验证后直接登录。其他绑定邮箱的新设备先完成八位验证码验证，再由超管批准。已明确拒绝或撤销的设备不能通过自助确认恢复。
4. 普通成员还需获得面向这个设备的项目授权。没有邮箱的成员仍需超级管理员审批新设备。
5. 在“项目与 MCP”中绑定服务端项目与本地工作目录。点击“MCP 配置”，可以复制通用 stdio 配置；Claude Code 可以预览并确认写入项目 `.mcp.json`，已有配置会备份。
6. 在 harness 中重新加载 MCP。先调用 `hub_check_version`，检查通过后用 `hub_get_project` 确认项目。管理员在网页后台同步文档后，拥有 `documents:read` 的成员可以检索。

默认关闭窗口后后台继续运行，通知区域托盘菜单的“退出桌面后台”才会完全退出。桌面设置可调整托盘运行、消息推送、推送摘要和开机启动，也可发送测试通知。完全退出后 MCP 会报告桌面端离线。移动应用文件夹后，请重新生成 MCP 配置。本机生成的配置包含绝对路径，请勿提交到 Git。

安装程序为当前 Windows 用户创建应用快捷方式和“Agent Hub 管理后台”网站快捷方式。应用顶部、侧栏和托盘菜单也能直接打开后台。卸载保留账号缓存和本地工作目录；已经写入项目的 MCP 配置可由用户移除。

推送来自在线 SSE 项目进度与权限变化。后台在线时可接收其他设备的进度；短时离线重连会补齐。首次绑定不弹出全部历史记录。同设备已显示的事件不重复通知。推送摘要默认隐藏，点击通知打开项目动态。Windows 免打扰或应用通知被关闭时，系统可能不显示弹窗，可使用“发送测试通知”检查。

从旧版本升级时先退出原桌面后台，再运行新版本。账号和绑定沿用原用户数据目录。在“MCP 配置”中重新预览并写入新的应用路径；软件能核验归属的连接会安全更新，其他条目会保留。0.1.0 安装后若文件又被手动修改，无法核验旧项归属时会提示冲突，核对后可手动移除旧项再写入。

## 通过 Agent 创建项目

超管登录后，点击右上角“管理 MCP”，或“项目与 MCP → 管理 MCP 配置”。复制配置到 AI 开发工具的 MCP 设置并重新加载。即使平台中还没有任何项目，也能连接这个管理入口。

可以直接对 Agent 说：“列出已有项目；如果没有 kms，就创建标识为 kms、名称为 kms 的项目。”管理工具为 `hub_list_projects` 和 `hub_create_project`；后者的参数为 `slug`、`name`、稳定的 UUID `operation_id`。同一次创建重试保持同一 UUID。创建完成后项目会出现在 PC 列表，可选择工程文件夹建立项目连接。

管理连接绑定当前账号和设备，每次调用都会重新向服务器核验超管身份，创建继续走已有服务器审批身份、审计和幂等接口。普通项目连接提供本项目读写工具；管理连接提供项目列表和创建。退出登录停止访问，重新登录同账号可恢复；在管理配置中“停用管理连接”会立即使原连接失效。切换账号后原管理连接不可使用。

管理 MCP 配置保存本机桥接路径，访问凭证和设备私钥留在桌面端。它创建平台项目记录；工程目录绑定及文档源配置沿用现有入口。

0.6.1 一体安装会配置 `agent-hub-setup`，无需再手工复制管理连接。这个安装连接也支持 `hub_list_projects`、`hub_create_project`，并增加 `hub_connection_status`、`hub_connect_project`。普通成员从服务器当前授权中列出项目，创建仍限超管。每个工程生成独立的固定项目连接，安装连接不直接读取任意项目资料。

安装连接绑定首次成功登录的服务器账号和设备，退出后不能执行项目操作；切换账号不会自动继承。桌面设置可停用，或重新授权后再次运行安装入口。连接配置带有固定连接 ID，旧 ID 不能因描述文件被替换而恢复权限。安装与项目配置会备份原文件、保留其他连接，检测同名修改和路径链接；已识别的自身配置可以更新。

## 对话启动与自动更新

右上角、桌面设置和托盘菜单均有“在线升级”，未登录时也可使用。点击后检查已批准稳定渠道，有新版即下载、验签、校验文件并自动重启；界面显示进度。账号与 MCP 绑定保留，失败可重试。0.4.0 旧版可在“账号与设备 → 检查客户端更新”升级，也会在完全退出后台后重新启动时自动检查。

已有 0.2.0 或更早版本的设备先手动安装当前版本，并在 harness 中更新一次 MCP 配置。0.3.1 及以上可从相同渠道自动更新；希望在系统中安装并创建快捷方式时运行 EXE 安装程序。账号和项目绑定沿用同一个桌面用户数据目录。

- 桌面端启动和 MCP 握手时检查已发布版本。每次开始或恢复项目对话时，调用 `hub_check_version`。只有 `can_continue: true` 才继续项目操作。
- 在“项目与 MCP → MCP 配置”复制对话启动规则，加入 harness 的项目规则。复用 MCP 连接的 harness 也会在项目工具调用前检查版本。
- Codex 可复制会话启动钩子，合并到项目的 `.codex/hooks.json`，再在支持钩子的客户端审查并信任。钩子在新会话或恢复会话时执行。[OpenAI Docs](https://learn.chatgpt.com/docs/hooks)
- Claude Code 可复制会话启动钩子，合并到项目的 `.claude/settings.local.json`。钩子通过本机命令检查版本，可以在 MCP 连接完成前运行。[Claude Code 钩子文档](https://code.claude.com/docs/en/hooks#sessionstart)
- 发现新版时，桌面端自动下载完整便携包，校验 Ed25519 签名、ZIP 的 SHA-256 和包内文件摘要。更新过程中 MCP 返回更新状态，项目调用暂停。当前正在提交的调用结束后切换并重启。
- 新版成功加载后启用新目录，账号、项目绑定和正在运行的 MCP 桥接进程可以恢复。新版启动失败会重新打开上一版，桌面端提供“重试更新”。发布清单无法核验时，MCP 项目调用也会暂停。

保留初次解压目录，其中的可执行文件仍可打开已激活的新版本，并用于之前生成的 MCP 配置。新版保存在桌面用户数据目录下的 `desktop-updates/versions`，旧版本目录保留以便恢复。自动更新适用于 Windows x64，签名用于校验发布内容。Windows 应用代码签名和 macOS 安装包仍待交付。其他 harness 使用通用规则和 MCP 检查入口，原生钩子需按客户端验收。

## 当前功能

- 本设备签名登录、邮箱验证码、新设备审批与已有会话续期。
- 多项目工作目录绑定，项目连接固定，不随界面切换。
- MCP：`hub_get_project`、`hub_list_progress`、有 `tasks:write` 授权时的 `hub_report_progress`。
- 有 `documents:read` 授权时提供 `hub_get_document_index`、`hub_search_documents`、`hub_read_document`。支持中文文字片段匹配；结果含路径、Git 提交号、索引快照与摘要。读取与翻页时传回 `snapshot_id`，索引变化会提示重新查询。
- 服务器持久保存进度，SSE 按游标补齐，显示最近 100 条；在线其他设备上报时触发桌面通知。
- 服务端在每次受管请求及流连接存续期间重查权限；撤权后停止对应 MCP 操作并显示拦截。
- 凭证通过 Electron safeStorage / Windows 系统保护加密落盘。harness 配置仅含本机连接命令；设备私钥和服务器 Token 不进入配置或 renderer。
- 离线启动后自动重试；会话/设备失效时停止重试并提示重新登录。进度流按心跳检测中断，重连后的新进度仍可触发通知。

## 0.1.1 修复

- 退出先冻结本机连接、清空会话并保存，再请求服务器撤销；晚到的刷新响应不能恢复登录。
- 授权变更时取消旧项目事件流，防止旧撤权响应覆盖新连接；并发首次调用只创建一个项目会话。
- 写权限不足及参数错误不再使整个读取连接失效；会话到期、设备撤销和网络故障分别处理。
- 离线启动自动恢复原身份；登录登记丢包重试复用已保存的设备密钥。
- 允许更新有归属的旧 MCP 配置，保持原文件备份及其他连接；用户修改过的同名项继续拒绝覆盖。
- 支持完整 Unicode 进度分页；stdio 关闭时等待输出写完，避免大响应截断。

0.2.0 增加文档工具及权限校验。本机 23 项测试、服务端 53 项测试通过；浏览器实际配置/同步/查询与真实 Electron stdio MCP 联调通过，包含中文路径、提交引用、跨项目隔离和撤权后拒绝读取。两套设备身份运行于同一 Windows 工作站，尚未用两台物理设备验收。

`hub_search_documents` 示例：`{"query":"系统架构","limit":20}`。用返回的 `path` 和 `snapshot_id` 调用 `hub_read_document`。文档是项目资料，不具有修改系统指令或工具权限的效力。

`hub_report_progress` 示例参数：

```json
{
  "operation_id": "b78fb988-4cf4-4a3e-aabd-1789bf3a5239",
  "status": "checkpoint",
  "summary": "登录接口已完成，等待联调",
  "detail": "接口测试通过，下一步验证邮件重试。",
  "task_reference": "AUTH-12"
}
```

同次报告重试保持相同 UUID 和内容；不同报告使用新 UUID。状态支持 `running`、`checkpoint`、`blocked`、`completed`。报告只代表进度通告，不改变正式任务状态。Git 提交引用可通过 `git_commit` 上报，当前不会自动抓取仓库或上传工作文件。

当前登录沿用内部 REST 设备协议。日志和代码快照分别补传；已登记日志的原作者设备仍获授权时可以补传原快照，即使租约后来结束。撤权使用独立的原设备上传通道，服务器确认后才按项目安装收据清理，PC“撤权交接”显示单独状态。标准 OAuth/PKCE 仍待实施。

## 任务与逐轮工作日志

PC 侧栏“任务与日志”按连接查看服务端任务、专注范围、执行者与日志；列表每 5 秒刷新。流程事件继续通过已保存游标的 SSE 接收并推送。完整日志需要单独的 `logs:read` 授权，无此权限仅能看本人原文。Web 同名页面可管理项目规则、创建和确认流程；人工资料任务可网页认领，代码任务通过工程 MCP 认领。

项目 MCP 新增 `hub_list_tasks`、`hub_get_task`、`hub_create_task`、`hub_claim_task`、`hub_heartbeat_task`、`hub_release_task`、`hub_write_worklog`、`hub_list_worklogs`、`hub_submit_task`、`hub_decide_task`。工具按当前能力授权展示；每次调用仍由服务器鉴权。每个开发执行者显式持有 `task_id`、`run_id`、`lease_epoch`，10 分钟租约、约 2 分钟心跳；其他设备接手后旧 epoch 不能提交。

正式流程为需求确认、设计、可行性、认领开发、提交检查点、评审、测试、发布确认。评审和测试绑定当前日志版本，作者自审仅允许超管明确记录例外原因。子任务未完成时父任务不能完成。发布确认不自动执行部署。

默认代码任务须先 `hub_prepare_work`、读取后 `hub_acknowledge_work`，修改前 `hub_check_changes`。每轮 `hub_write_worklog` 采集实际清单、基线及改动，分别上传日志和加密代码快照。提交前重新采集，有后续变化就须记录新检查点；新建且绑定仓库的代码任务须有完整远程快照。`hub_list_worklogs` 返回摘要，`hub_read_worklog` 展开原文及备份、交付回执。Git 推送由服务端另查上游引用。没有系统级写入隔离。

桌面为已准备确认的运行约每 2 分钟续租，连续 10 分钟无代码或工具活动则停止。约每分钟观察变化，只保留该运行最新后台槽，不生成本轮工作说明。PC“本机检查点”可导出到新目录；已共享记录导出核验后可清理。每个最多 100 文件、4 MiB/文件、16 MiB 内容，本机最多 100 条；忽略文件、链接和 submodule 不受备份保证。退出桌面后台即停止这些工作。

PC 日志可“取回到本机检查点”，随后导出完整 `working-tree/` 到新目录；模型不接收代码正文，原工程不被覆盖。基线最多 1000 文件、16 MiB，变更最多 100 文件、16 MiB，单文件 4 MiB，本机总计 512 MiB。没有 Git 历史、忽略文件及个人凭证。多仓库与 Git 交付见随附 Skill 的 `references/repositories.md`；自动逐轮宿主钩子、长期记忆、向量检索及角色调度仍待实现。

## 本地数据与配置

- Electron 用户数据目录下的 `vault.bin` 保存加密账号、设备身份、会话与界面缓存；`work-checkpoints/` 逐条加密保存代码检查点和待发日志，不提供明文降级。
- `setup-mcp.json` 是一体安装的本机连接描述，`setup-installations/` 与 `setup-projects/` 保存配置归属和安装回执。这些是本机数据，不提交到 Git。Skill 生成的工作记录属于相应工程，进度上报不会自动上传原记录或代码。
- `bindings/*.json` 是仅在本机使用的连接描述文件。它包含可使用对应项目连接的本机秘密，应像本机凭证一样保护，不要共享或提交。
- 同一个操作系统用户下的恶意程序仍可能操作客户端，这种本机保护不能替代服务器权限检查。
- 写入 `.mcp.json` 前展示预览、校验原文件摘要并备份，保留其他 MCP 连接；停用连接后描述文件删除，已经写入的配置保留供手工移除。
- 本机没有长期离线授权：断网后的远程操作失败并保留工作。

## 开发

```powershell
npm ci
node node_modules/electron/install.js
npm test
npm start
npm run package:win
npm run installer:win
```

便携包在 `dist/AgentHub-<版本>-win-x64.zip`，安装程序在 `dist/installers/AgentHub-Setup-<版本>.exe`，均随附 SHA-256。打包器只拷贝应用白名单与 Electron 运行文件，根目录管理员明文备忘不进入任何发行包。NSIS 安装程序使用固定 AppUserModelID 建立开始菜单入口，应用通知沿用同一身份。[Electron Windows 通知要求](https://github.com/electron/electron/blob/main/docs/tutorial/notifications.md)

图标使用内置 imagegen 生成，原图为 `assets/agent-hub-source.png`，应用 PNG 为 `assets/agent-hub.png`，多尺寸 Windows ICO 为 `assets/agent-hub.ico`。可通过 Electron 运行 `scripts/prepare-icon.cjs` 从已生成原图导出图标。图标的生成规格为：深蓝圆角底、翡翠绿 A/桥形标记、三个协作节点、透明外缘、小尺寸清晰；应用、托盘、可执行文件与安装包共用该图标。

发布时递增版本号并生成新 ZIP，用 `node scripts/sign-release.cjs <发布私钥绝对路径>` 生成 `dist/stable.json`。发布私钥保管在发布机的受控目录，服务端只接收签名清单和公开安装包。先上传 ZIP 并核对 SHA-256，再替换 HTTPS 上的 `stable.json`。发布后的版本路径保持固定，新修订使用更高的版本号。

### 清单续签与失效处理（0.3.2）

签名清单新增 `metadata_version`、`issued_at`、`expires_at`；默认有效期 30 天，最长 31 天。联网检查拒绝到期、未来签发、编号回退和同编号替换，并保存已见最高编号。相同软件版本不能更换 ZIP；续签只提高清单编号和有效期。旧 0.3.1 仍能读取这份 schema 1 清单并升级，旧客户端自身没有这些新检查。

发布操作人每 14 天续签一次，保留本地 `dist/stable.json`。换发布机时先从正式渠道保存现有清单，再执行：

```powershell
node scripts/sign-release.cjs <发布私钥绝对路径> --previous <现有清单绝对路径> --days 30
node scripts/check-release.cjs
```

续签时保持已发布 ZIP 和展开目录原样，不重新打包。先离线核验新清单，再原子替换服务器 `stable.json`。`check-release.cjs` 校验公网签名和时效，剩余不足 72 小时退出码为 2，失效/网络异常为 1，可接入现有监控。私钥不放服务器，不以无人值守脚本自动读取离线私钥；监控与续签责任人必须在上线前落实。

到期或网络无法核验时暂停普通项目 MCP 操作；桌面与已安装、已校验的历史程序仍能启动，本地文件保留。校准错误的设备时间或发布有效清单后重试。客户端检测已记录检查时间的大幅回退，仍依赖操作系统时钟。该版本使用单一内置公钥，尚未实现 TUF 的角色分离、阈值签名和在线根密钥轮换；密钥丢失/泄露需受控分发带新信任根的客户端。

服务器数据库迁移及服务端测试请参照 `projects/agent-hub` 与项目设计文档；数据库仅在指定服务器上运行。
