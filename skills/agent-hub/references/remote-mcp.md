# 远程 MCP 连接

仅在用户选择云端资料读取和进展协调、宿主提供 HTTP MCP 与 OAuth 预注册支持时使用。完整开发仍通过桌面 MCP 采集本机代码、任务租约、逐轮记录、代码备份、Git 交付和撤权卸载。

1. 用户先在将完成 OAuth 授权的浏览器中登录后台、验证设备；后台“远程 MCP 连接”显示这个浏览器设备 ID。
2. 超管在同一页面批准客户端，固定用户、已批准设备、项目授权、仓库、准确回调地址及只读或协调范围。普通管理员和成员不能自行注册客户端。桌面与浏览器密钥不同，不混用设备 ID。
3. 将客户端 ID 与固定 MCP 地址填到宿主支持的远程 MCP 配置。地址格式为 `/mcp/projects/<project_id>/repositories/<repository_id>`；令牌不得放入 URL、Skill 或聊天。
4. 宿主启动 OAuth PKCE S256 登录，本人在同一已批准浏览器确认。回调、资源地址或设备不匹配时停止并由超管核对注册信息，不自动放宽授权。
5. 远程连接提供项目、任务、共享日志、文档分段及关键词记忆检索；有 `mcp:coordinate` 且平台授权允许时可提交进展通告。每次通告保留同一 `operation_id` 重试。进展不改变任务正式状态，也不证明代码已交付。
6. 本人在后台可断开自己的远程会话，超管可撤销整个客户端。账号、设备、项目或来源登录会话失效后，服务端拦截后续请求。远程入口没有本机安装收据或工作树；本机上传和卸载由桌面通道处理。

不支持预注册客户端的宿主不能据此声称已经接通。该入口不接收模型密钥、不执行本机 Shell、不转发任意目标 URL。OAuth 刷新轮换与邮箱及设备审批是不同环节。
