# 撤权交接

适用于服务端 0.8.0 / 桌面端 0.10.1 起提供的撤权收尾工具。项目成员移除、账号冻结/停用、设备撤销、仓库授权缩减或仓库归档后，普通权限立即失效。任务原租约被释放，接手人仍须重新认领。

1. 停止本项目普通开发、Git 推送、认领、提交和读取共享资料。调用 `hub_closeout_status` 了解本连接的交接状态；网络异常或自然会话过期本身不会产生卸载任务。
2. 服务端存在撤权任务时必须调用 `hub_run_closeout`。桌面在后台也会自动执行；程序使用原设备绑定的专用上传身份，仅允许保存原先任务的工作。Agent 不接收该凭证，不转运代码、归档或 Shell 命令。
3. `server_upload_confirmed: true` 表示本次收尾清单的代码已在服务器确认；`state: complete` 表示客户端按安装收据清理并回报成功。只有日志共享不能代替代码上传。自动收尾日志明确标注未运行测试，不代替此前人工工作说明或评审。
4. `blocked`、`conflicts`、上传超限、存储损坏或断网时保留工程、加密检查点和修改过的框架文件，普通操作保持关闭。在 PC“撤权交接”查看原因、重试；授权默认 30 天，过期请超管在 Web 延长。不要清空 Git、重置文件、绕过检查或自行删除目录。

程序只移除安装收据登记、归属当前项目且摘要相符的框架文件，以及仍与安装值相符的 MCP 项；支持登记的规则、脚本和测试文件。共享桌面端、通用 Skill、其他项目配置、业务代码和本机检查点保留。未登记的旧框架文件无法安全推断归属；修改过的文件报告冲突。

重新获得授权后，用新授权重新接入工程；旧连接保留停止状态。接手者从获准日志获取代码备份并导出至新目录，不复用原作者租约。客户端卸载回报不是远程擦除证明，MCP 也不能拦截宿主绕过工具的文件操作。
