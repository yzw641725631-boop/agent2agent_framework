# 宿主保护与本机执行

先检查版本并发现工具。旧连接没有以下工具时，说明需要更新；不生成未经核验的宿主配置。

## 安装并确认保护

1. 当前项目连接调用 `hub_preview_hooks(harness)`，核对目标、保护内容和正常宿主信任流程。
2. 用原 `preview_hash` 调用 `hub_install_hooks`。程序合并本连接条目并保存归属收据，保留其他设置；冲突时重新核对，不覆盖用户修改。
3. 用户按宿主正常流程信任和重新加载。调用 `hub_get_hook_status` 区分 `awaiting_host` 与 `observed`；写入配置并不证明宿主实际加载。
4. 认领并准备、确认运行，使用真实启动事件的 `session_key` 调用 `hub_bind_work_session`。修改前核验允许路径、当前租约和规则，每轮变更保存日志。

已适配的配置协议为 Codex、Claude Code、Cursor、Qoder、CodeBuddy；宿主真实触发仍需在所用版本核对。WorkBuddy、TRAE 原生生命周期接口尚未核验，不套用其他产品的配置。MCP 安装、原生钩子和自动执行是三个独立能力。

未识别工具及无法证明路径范围的命令会被拦截。保护不能限制用户直接编辑文件或独立外部程序，也不能替代操作系统隔离。只有本人明确要求卸载时才调用 `hub_uninstall_hooks`；撤权收尾按签发任务和安装收据处理。

## 启动原生开发工具

目前只核验 Codex 和 Claude Code 的固定 CLI 启动入口。其他工具继续使用本人打开的会话通过 MCP 接收待办。

- 本人先在 PC“本机执行”登记已安装的真实原生程序。框架核验文件路径与摘要，Windows 仅接收 exe；程序更新后重新登记。
- `hub_preview_execution` 指定已认领并准备确认的 `task_id/run_id/lease_epoch`、对应 `harness` 与 30–1800 秒时限。须先安装保护配置，不能传入任意命令或参数。
- 本人在桌面核对任务、目录和程序并通过原生对话框批准。批准绑定身份、设备、程序、规则、记忆和时限，两分钟过期且只消费一次。MCP 没有批准接口。
- `hub_start_execution` 使用该次批准；`hub_execution_status` 看实际状态，`hub_stop_execution` 请求停止。运行继续使用本人的宿主登录、信任和权限，不自动批准宿主权限。
- 断网、撤权、超时或桌面退出会停止观察到的进程。守护进程监视桌面管道与心跳；独立逃逸的后台程序不属于本机制保证范围。
- `exited` 只表示程序退出，不能代表任务完成、测试通过、代码已经共享或发布。仍核对工作日志、备份、Git 和流程回执。
- 异常恢复未取得可靠停止回执时，禁止重新启动同目录任务，由本人核查旧进程。不能凭可能被复用的历史 PID 自动杀进程。
- 原始输出不存入运行记录；保留字节数、摘要及退出记录。断网后补传同一冻结回执和 `operation_id`，不伪报已共享。
