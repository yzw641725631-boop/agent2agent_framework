# 开发记录与交接

沿用项目已有工作日志。原 install 框架已部署时，优先使用其当前项目的工作日志目录；没有现成约定时，可在当前工程的 `.agent-hub/work-notes/` 按日期和任务创建 Markdown。只在本项目内记录，不把不同授权工程的数据合并到通用 Skill 目录。

每个改代码轮次至少记录：

```markdown
# 日期 · 任务

- 目标与范围：工程、目标端、要解决的问题。
- 变更：实际改动的文件、关键决定及原因。
- 验证：执行的检查与结果；未执行的检查如实列出。
- 当前状态：完成内容、失败或未确认事项、未提交工作位置。
- 接手下一步：能直接执行的下一动作及必要注意点。
- 代码引用：已有提交号；尚未提交时标明工作区状态。
- 平台记录：task_id、run_id、lease_epoch、operation_id；返回的日志 ID、receipt_hash 或待补报状态。
```

原记录保留，通过项目已有 Git 流程留版本。不要为了写记录擅自提交、推送代码或上传全部工作目录。需要临时离开时，把未提交改动、验证结果和下一步说明清楚；当前进度工具不会自动保存开发文件。

恢复任务时先读当前摘要、相关记录索引和必要变化，再展开有证据的原文。可以更新项目已有精简记忆以记录稳定结论、约束及未完成事项，并链接原记录；避免不断复制整段历史。不要将这种 Agent 执行的记录与摘要描述成已经实现的服务器强制记忆或自动交接机制。

有有效开发租约及 `tasks:write` 时，用 `hub_write_worklog` 保存本轮原文。字段包括 `summary`、`notes`、`changed_paths`、`tests`、`next_steps`、`outcome` 和可选 `git_commit`。`outcome` 为 `checkpoint`、`blocked` 或 `failed`；总记录最多 64 KiB，不要粘贴整段终端输出。

写入成功保存日志 ID 和 `receipt_hash`。服务器记录不可覆盖；纠正错误应追加日志说明。只上报实际任务范围内的相对路径。没有执行验证时如实填写原因，不捏造通过。`git_commit` 是未核验的引用，不能代替可恢复代码。

`hub_list_worklogs` 按任务读取最近日志并分页；`logs:read` 单独授权后才能查看同事原文，无此权限仅返回本人日志。公共动态只通知“工作日志已保存”，不复制业务原文。恢复时优先读取任务状态、最近必要日志和精简的本地记忆，按需翻页。

服务器不自动截获每次代码编辑。Skill 要求每轮记录，仍需执行者实际调用；离线失败时本地 Markdown 是待补报原文，不能称为已共享或已备份代码。
