# 开发记录与交接

沿用项目已有工作日志。原 install 框架已部署时，优先使用其当前项目的工作日志目录；没有现成约定时，可在当前工程的 `.agent-hub/work-notes/` 按日期和任务创建 Markdown。只在本项目内记录，不把不同授权工程的数据合并到通用 Skill 目录。

每个改代码轮次至少记录：

```markdown
# 日期 · 任务

- 目标与范围：工程、目标端、要解决的问题。
- 变更：实际改动的文件、关键决定及原因。
- 验证：执行的检查与结果；未执行的检查如实列出。
- 当前状态：完成内容、失败或未确认事项、未提交工作位置。
- 接手下一步：能直接执行的下一动作及必要注意点。
- 代码引用：已有提交号；尚未提交时标明工作区状态。
- 平台记录：task_id、run_id、lease_epoch、operation_id；返回的日志 ID、receipt_hash 或待补报状态。
```

原记录保留，通过项目已有 Git 流程留版本。不要为了写记录擅自提交、推送代码或上传全部工作目录。Markdown 也须位于任务允许路径；记录位置超出范围时用正式日志保存，不为写日志扩大目录权限。进度通告不备份文件；代码任务的桌面检查点另行保存实际改动。

恢复任务时先读当前摘要、相关记录索引和必要变化，再展开有证据的原文。可以更新项目已有精简记忆以记录稳定结论、约束及未完成事项，并链接原记录；避免不断复制整段历史。不要将这种 Agent 执行的记录与摘要描述成已经实现的服务器强制记忆或自动交接机制。

有效租约及 `tasks:write` 下，用 `hub_write_worklog` 保存本轮原文。字段为 `summary`、`notes`、`tests`、`next_steps`、`outcome`；`outcome` 为 `checkpoint`、`blocked` 或 `failed`。代码任务优先省略 `changed_paths` 和 `git_commit`，由桌面采集实际值；显式路径必须完全匹配实际清单。总记录最多 64 KiB，不粘贴整段终端输出。

代码任务先返回本机回执：`state: shared` 与 `server_confirmed: true` 后保存 `server_receipt.id`、`receipt_hash`。这是日志回执；代码另看 `server_code_backup`、`backup_state`、`backup_error` 和 `code_receipt`。`pending` 是加密待发，恢复网络后自动重试；`blocked` 保留本机工作，旧租约、旧规则或撤权请求不会自动越过限制。代码备份失败时不重新生成日志以冒充成功。服务器日志不可覆盖，纠正错误须追加。未执行验证时如实写明；Git 交付须另核对 `delivery`。

`hub_list_worklogs` 按任务返回摘要索引，`hub_read_worklog` 按 ID 展开必要原文；`logs:read` 单独授权后才能查看同事日志，否则仅本人。上下文准备最多附 5 条获准摘要；公共动态不复制业务原文。按需翻页，避免每轮重读全历史。

PC“本机检查点”显示独立逐轮检查点及后台观察槽。桌面托管运行约每分钟观察实际改动，只有发生变化才更新后台槽；它没有本轮意图、测试说明，也不自动共享。显式日志保存独立检查点，不会被后台观察覆盖。

检查点用系统凭证保护加密，重启可重新读取。快照变更最多 100 文件、4 MiB/文件、16 MiB；完整 Git 基线另限 1000 文件、16 MiB。本机最多 100 条、合计 512 MiB，服务端按项目和站点设置配额。超限必须保留工作并处理原因，不能跳过门禁或声称已备份。Git 忽略文件不采集，链接、submodule、冲突和凭证路径拒绝；完整 Git 历史、依赖缓存与个人凭证不在备份内。

新版快照自带基线，程序校验 Git commit/tree/blob 和改动摘要。导出只向新的独立目录写 `checkpoint.json`、`changed-files/`、完整 `working-tree/`；核对后在后者接续代码，Git 仓库历史和依赖需另行准备。旧版仅有改动的检查点仍须在另一目录检出 `base_commit`，再核对并应用变更及删除清单。不能把工作树导出当作完整 Git 镜像。已共享日志的检查点可在导出后显式清理，清理前重新核验说明和全部导出代码；损坏时保留加密副本。

跨设备接手：用 `hub_read_worklog` 取得获准日志及 `snapshot`，调用 `hub_download_work_backup(task_id, worklog_id, operation_id)`。下载使用当前身份，按项目、仓库和日志可见性复核权限，并校验归属与摘要；同次重试保持同一 operation_id。服务器保存的代码不因原作者被移出项目而消失，有权限接手人才可取回。工具仅返回本机检查点回执，PC“本机检查点”再导出；不会把代码正文注入模型，也不会覆盖工作区或续用作者租约。

对已登记成功的日志，仍有权限的原作者设备可补传原快照，即使租约后来结束；不能补写旧租约日志、替换快照或修改新任务。被撤权账号或设备使用独立的[撤权收尾通道](revocation.md)，不能复用普通会话。新建且绑定仓库的代码任务提交评审前，服务端要求最新日志有对应完整快照，并验证制品可解密。

服务器不截获每次编辑；Skill 要求每轮记录仍需执行者调用。服务器加密卷备份须与数据库、解密密钥共同备份；接收回执不等于已完成异地容灾。当前没有统一的宿主轮次钩子或长期记忆自动提炼。退出桌面后台后观察、补传、收尾、心跳和 MCP 都停止。
