# 用量与检索核验

工具存在时才调用。`hub_get_usage` 读取当前有权范围内已收到的用量；PC/Web 有“用量与预算”入口。

- 开工包大小由程序测量，Token 估算明确标记估算方法，不等于宿主实际调用或账单。
- `hub_report_usage` 只填写宿主真实返回的输入、输出、缓存输入和可选费用。缓存输入包含在输入中，不重复计费。保留真实来源的引用摘要与执行身份。
- 同一回执的报告保持同一 `reference_hash`，请求重试保持同一 `operation_id`。不可变回执不允许重报时改数值。
- 没有宿主用量数据时明确“未知”，不填 0 冒充没有消耗，也不猜费用。现有报告未核对供应商账单。
- 负责人通过 `hub_configure_usage_budget` 或后台发布额度修订。额度依据已收到的项目月度报告；达到额度时停止新的受管开发，仍可保存日志和交接。它不能限制独立外部程序或未上报调用。

检索核验用真实问题和当前有效、本人可读的来源卡片 ID。`hub_evaluate_memory` 实际运行检索并保存 Recall@k、MRR、所用方法与降级结果；按需用 `hub_list_memory_evaluations` 查历史。先核对工具实际名称和参数；评测不等于模型理解，也不保证后续所有问题均命中。

评测结果继承全部引用来源的权限；某来源失效或撤权时不能用历史结果继续展开。不要把不可读来源的 ID、标题、计数或内容写入其他仓库的记忆。
